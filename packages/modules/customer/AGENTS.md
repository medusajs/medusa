# @medusajs/customer

Customer Module (`Modules.CUSTOMER`, container key `"customer"`). Stores customers (guest and registered), their addresses, and customer groups. Authentication is not here: registered customers are tied to an Auth Module identity via `app_metadata.customer_id`.

## Using this package

- Registered by default via `defineConfig` as `@medusajs/medusa/customer`. No module options.
- Resolve: `container.resolve(Modules.CUSTOMER)` (`ICustomerModuleService`).
- Prefer core-flows workflows (`@medusajs/medusa/core-flows`) such as `createCustomersWorkflow` and `createCustomerAccountWorkflow` (creates the customer and sets `customer_id` on the auth identity). They also handle default-address flipping and emit the public events.

```ts
const customerModule = container.resolve(Modules.CUSTOMER)

const customer = await customerModule.createCustomers({
  email: "jane@example.com",
  addresses: [{ address_1: "1 Main St", is_default_shipping: true }],
})

await customerModule.updateCustomers(customer.id, { first_name: "Jane" })
await customerModule.addCustomerToGroup({
  customer_id: customer.id,
  customer_group_id: groupId,
})
```

### Data models (`src/models`)

- `Customer` (`cus_`): `email`, `first_name`, `last_name`, `company_name`, `phone`, `has_account`, `created_by`, `metadata`; `addresses` (cascade delete), `groups` (many-to-many via `CustomerGroupCustomer`). Unique on (`email`, `has_account`) among non-deleted rows.
- `CustomerAddress` (`cuaddr_`): address fields plus `is_default_shipping` / `is_default_billing`. Partial unique indexes allow one default of each per customer.
- `CustomerGroup` (`cusgroup_`): `name` (unique among non-deleted, translatable), `metadata`, `created_by`.
- `CustomerGroupCustomer` (`cusgc_`): pivot with `created_by`, `metadata`.

### Custom service methods (`src/services/customer-module.ts`)

- `createCustomers(data | data[])`: also creates nested `addresses`.
- `updateCustomers(id | ids[] | selector, data)`, `updateCustomerGroups(...)`, `updateCustomerAddresses(...)`: same `(idOrIdsOrSelector, data)` shape.
- `addCustomerToGroup(pair | pairs)`, `removeCustomerFromGroup(pair | pairs)` with `{ customer_id, customer_group_id }`.
- `createCustomerGroups`, `createCustomerAddresses`; everything else is generated by `MedusaService`.

### Events

- `customer.created`, `customer.updated`, `customer.deleted` (`CustomerWorkflowEvents`) are emitted by core-flows workflows, not by the module.
- The module emits internal mutation events like `customer.customer.created`, `customer.customer-address.updated`.

### Module links

- Stored: `Customer` <-> payment `AccountHolder` (`customer.account_holders`, `link-modules/src/definitions/customer-account-holder.ts`).
- Read-only: `cart.customer` / `customer.carts`, `order.customer` / `customer.orders` (joined on `customer_id`).

## Development

```bash
yarn build
yarn test                  # src unit tests (none currently)
yarn test:integration      # integration-tests/__tests__/services/customer-module/index.spec.ts (Postgres)
yarn test:integration -t "<test name>"
yarn migration:create      # after any change to src/models; never hand-write migrations
```

## Gotchas

- `updateCustomers` takes `(ids, data)`, not an array of `{ id, ...data }` objects. An array is always treated as a list of IDs, so `updateCustomers([{ id, first_name }])` does not do a batch update.
- The same email can exist twice: once as a guest (`has_account: false`) and once registered (`has_account: true`).
- Setting a second default shipping/billing address for a customer violates a unique index. The module does not unset the previous default; the core-flows steps `maybe-unset-default-*-addresses` do.
- Deleting a customer cascades to its addresses and detaches group memberships; deleting a group only detaches customers.
