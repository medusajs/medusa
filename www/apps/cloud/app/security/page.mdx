# {metadata.title}

In this guide, you'll learn about Medusa Security and how it protects your Medusa projects on Cloud.

## What is Medusa Security?

Medusa Security is a set of security features that Cloud applies to the traffic reaching your Medusa projects. It filters malicious requests, absorbs attacks, and blocks automated abuse before they reach your Medusa application.

Medusa Security is available for all [plans](../pricing/page.mdx).

When you self-host Medusa, you're responsible for setting up a firewall, mitigating attacks, and keeping up with newly discovered vulnerabilities. On Cloud, Medusa handles this for you, so your projects are protected from the moment they go live without configuring firewall rules, DDoS mitigation, or bot protection yourself.

### Security Features

Medusa Security includes the following features:

- [Configurable Features Per Environment](#configurable-security-features-per-environment): Enable or disable specific security features for different environments of your project.
- [Medusa Ruleset](#medusa-ruleset): Blocks requests that try to exploit vulnerabilities and attack patterns specific to Medusa applications.
- [Basic Protection Ruleset](#basic-protection-ruleset): Blocks requests that try to exploit common web attacks and widely exploited vulnerabilities.
- [DDoS Protection](#ddos-protection): Detects and mitigates distributed denial-of-service (DDoS) attacks.
- [Bot Detection](#bot-detection): Blocks requests coming from malicious bots.
- [Security Analytics](./analytics/page.mdx): View the requests that security features allow or block, and look up a blocked request by its Ray ID.

## Configurable Security Features Per Environment

Each Medusa Security feature applies to the environments you select for it. For example, you can apply bot detection to your Production environment only, so that it doesn't interfere with automated tests that send requests to your [preview environments](../environments/preview/page.mdx).

For each feature, you can select:

- **Environment types**: Production, Long-lived, or Previews. The feature applies to every environment of the selected types, including environments you create later.
- **Specific environments**: Individual environments of your project. The feature applies to those environments only.

You can combine both. For example, you can apply a feature to the Production environment type and to a specific [long-lived environment](../environments/long-lived/page.mdx), such as Staging.

To manage the environments of a feature, check the steps below relevant to the feature you want to configure.

<Note>

For Production environments, it is recommended to enable all security features to ensure maximum protection for your live application.

</Note>

## Medusa Ruleset

The Medusa Ruleset is a set of security rules that Medusa maintains to protect Medusa applications from known vulnerabilities and attack patterns.

While the [Basic Protection Ruleset](#basic-protection-ruleset) covers general web attacks, the Medusa Ruleset focuses on threats specific to Medusa applications. Medusa continuously monitors for new vulnerabilities and attack patterns identified in the Medusa open source project and deploys corresponding protections to the Medusa Ruleset.

This protects your projects even before you [update your Medusa application](../update-medusa/page.mdx) to a version that fixes the vulnerability.

<Note type="Important">

You should still update your application regularly to receive the fixes in your codebase.

</Note>

### Configure Environments for the Medusa Ruleset

To configure which environments the Medusa Ruleset applies to:

1. If you're in a different organization, [switch to the organization](../organizations/page.mdx#switch-organization).
2. Click **Projects** in the sidebar and select the project you want to manage.
3. In the project's dashboard, click **Security** in the sidebar, then click **Settings**.
4. In the "Medusa Ruleset" section, click the **Environments** dropdown.
5. Select the environments or environment types where you want to enable the feature.

<Note type="warning">

If you deselect all environments, the feature is turned off for your project. An environment that a feature doesn't apply to doesn't receive its protection.

</Note>

## Basic Protection Ruleset

The Basic Protection Ruleset is a managed web application firewall (WAF) ruleset that protects your projects against common web attacks and widely exploited vulnerabilities. For example, it can help defend against SQL injection and cross-site scripting (XSS) attacks.

Medusa inspects incoming requests, such as their URLs and headers, and blocks requests that match known attack patterns. This stops automated scanners that probe every server on the internet for these vulnerabilities before they reach your Medusa application.

The ruleset receives updates whenever a new wide-ranging vulnerability emerges, so your projects stay protected against new threats without any action on your part. Its rules also aim to minimize false positives, so they don't block legitimate traffic to your Medusa application.

## DDoS Protection

A distributed denial-of-service (DDoS) attack floods your application with traffic from many sources to make it unavailable to your customers.

Medusa Security protects your projects against DDoS attacks at both the network and application levels:

- **Network-level attacks**: Floods of traffic that target the network and transport layers, such as TCP-based attacks.
- **Application-level attacks**: Floods of HTTP requests that target your Medusa application or storefront.

DDoS protection detects attacks automatically and mitigates them as they happen, without manual intervention. Legitimate traffic continues to reach your application while Medusa mitigates the attack.

## Bot Detection

Bots generate a large share of internet traffic. While some bots are useful, such as search engine crawlers, others scrape your data, try to take over customer accounts, or overload your application.

Medusa Security analyzes each incoming request to determine whether it comes from a human or an automated source. It blocks requests only when it's certain that they come from a malicious bot, which keeps the risk of blocking real customers low.

Bot detection doesn't block verified bots, such as search engine crawlers, so your storefront's search engine visibility isn't affected.

<Note>

If you have scripts or services that send requests to your Medusa application, make sure they send a `User-Agent` header. Bot detection treats requests with a missing or empty `User-Agent` header as automated and potentially malicious.

</Note>
