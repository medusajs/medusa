# {metadata.title}

In this guide, you'll learn about Medusa Security and the security features it applies to your Medusa projects on Cloud.

## What is Medusa Security?

Medusa Security is a set of security features that Cloud applies to the traffic reaching your Medusa projects. It filters malicious requests, absorbs attacks, and blocks automated abuse before they reach your Medusa application.

When you self-host Medusa, you're responsible for setting up a firewall, mitigating attacks, and keeping up with newly discovered vulnerabilities. On Cloud, Medusa handles this for you, so you can focus on building your commerce application instead of maintaining security infrastructure.

Medusa Security is available to all Cloud customers, on every plan. To use it, you [enable Medusa Security](#enable-medusa-security) from your project's **Security** page. You can then [turn each feature on or off](#manage-features) individually.

Medusa Security includes the following features:

- [Basic Managed Ruleset](#basic-managed-ruleset): Blocks requests that try to exploit high-impact and widely exploited web vulnerabilities.
- [Medusa-Managed Ruleset](#medusa-managed-ruleset): Blocks requests that try to exploit known vulnerabilities specific to Medusa applications.
- [DDoS Protection](#ddos-protection): Detects and mitigates distributed denial-of-service (DDoS) attacks.
- [Bot Detection](#bot-detection): Blocks requests coming from malicious bots.

---

## Enable Medusa Security

Medusa Security is off by default. You enable it for each project from the project's **Security** page.

To enable Medusa Security:

1. Go to your project's dashboard.
2. Click **Security**.
3. Enable Medusa Security.

## Manage Features

After you enable Medusa Security, you can turn each of its features on or off individually. For example, you can turn off bot detection if it interferes with an integration that sends automated requests to your Medusa application.

To manage the features:

1. Go to your project's dashboard.
2. Click **Security**.
3. Use the toggle next to a feature to turn it on or off.

<Note>

DDoS protection is off by default, even after you enable Medusa Security. Turn it on from the **Security** page to protect your project against DDoS attacks.

</Note>

## Basic Managed Ruleset

The Basic Managed Ruleset is a web application firewall (WAF) ruleset that protects your projects against high-impact and widely exploited vulnerabilities. It inspects incoming requests, such as their URLs and headers, and blocks requests that match known attack patterns. This stops automated scanners that probe every server on the internet for these vulnerabilities before they reach your Medusa application.

The ruleset receives updates whenever a new wide-ranging vulnerability emerges, so your projects stay protected against new threats without any action on your part. Its rules also aim to minimize false positives, so they don't block legitimate traffic to your Medusa application.

---

## Medusa-Managed Ruleset

The Medusa-Managed Ruleset is a ruleset that Medusa maintains to protect against known vulnerabilities in Medusa applications.

While the [Basic Managed Ruleset](#basic-managed-ruleset) covers general web vulnerabilities, the Medusa-Managed Ruleset targets threats specific to Medusa. When Medusa discovers or receives a report of a vulnerability, it adds rules that block requests trying to exploit it.

This protects your projects even before you [update your Medusa application](../update-medusa/page.mdx) to a version that fixes the vulnerability. You should still update your application regularly to receive the fixes in your codebase.

## DDoS Protection

A distributed denial-of-service (DDoS) attack floods your application with traffic from many sources to make it unavailable to your customers.

Medusa Security protects your projects against DDoS attacks at both the network and application levels:

- **Network-level attacks**: Floods of traffic that target the network and transport layers, such as TCP-based attacks.
- **Application-level attacks**: Floods of HTTP requests that target your Medusa application or storefront.

When you [turn on DDoS protection](#manage-features), it detects attacks automatically and mitigates them as they happen, without manual intervention. Legitimate traffic continues to reach your application while Medusa mitigates the attack.

---

## Bot Detection

Bots generate a large share of internet traffic. While some bots are useful, such as search engine crawlers, others scrape your data, try to take over customer accounts, or overload your application.

Medusa Security analyzes each incoming request to determine whether it comes from a human or an automated source. It blocks requests only when it's certain that they come from a malicious bot, which keeps the risk of blocking real customers low.

Bot detection doesn't block verified bots, such as search engine crawlers, so your storefront's search engine visibility isn't affected.

<Note>

If you have scripts or services that send requests to your Medusa application, make sure they send a `User-Agent` header. Bot detection treats requests with a missing or empty `User-Agent` header as automated and potentially malicious.

</Note>
