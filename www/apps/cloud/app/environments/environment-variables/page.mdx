# {metadata.title}

In this guide, you'll learn how to manage environment variables of long-lived and preview environments in Cloud.

Environment variables are key-value pairs of sensitive information, such as API keys and credentials. Instead of hardcoding these variables in your codebase, you should store them as environment variables.

You can manage an environment's variables in its **Environment variables** settings. You can manage environment variables for the environment's Medusa backend and storefront (if applicable).

## Restricted Environment Variable Names

The following environment variable names are reserved by Cloud and you can't use them in your environment:

- `NODE_ENV`
- `EXECUTION_CONTEXT`
- `DATABASE_URL`
- `REDIS_URL`
- `MEDUSA_WORKER_MODE`
- `PORT`
- `K_SERVICE`
- `K_CONFIGURATION`
- `K_REVISION`
- `K_CONTAINER_NAME`
- `K_INTERNAL_POD_NAME`
- `K_INTERNAL_POD_NAMESPACE`
- `K_LOCAL_ADDR`
- `K_PROTOCOL`
- `SESSION_STORE`
- `DYNAMO_DB_SESSIONS_TABLE`
- `DYNAMO_DB_SESSIONS_HASH_KEY`
- `DYNAMO_DB_SESSIONS_PREFIX`
- `AWS_ACCESS_KEY_ID`
- `AWS_SECRET_ACCESS_KEY`
- `AWS_REGION`
- `MEDUSA_CLOUD_API_KEY`
- `MEDUSA_CLOUD_ENVIRONMENT_HANDLE`
- `MEDUSA_CLOUD_ENVIRONMENT_TYPE`
- `MEDUSA_CLOUD_ENVIRONMENT_NAME`
- `MEDUSA_CLOUD_PROJECT_HANDLE`
- `MEDUSA_CLOUD_EMAILS_ENDPOINT`
- `MEDUSA_CLOUD_SEARCH_ENDPOINT`

## System Environment Variables

Cloud automatically provides the following system environment variables in all environments at both runtime and build time:

- `MEDUSA_CLOUD_ENVIRONMENT_HANDLE`: The unique handle/identifier for the environment
- `MEDUSA_CLOUD_ENVIRONMENT_TYPE`: The type of environment (`production`, `preview-instance`, or `long-lived`)
- `MEDUSA_CLOUD_ENVIRONMENT_NAME`: The display name of the environment. For example, "Production" or "Staging".
- `MEDUSA_CLOUD_PROJECT_HANDLE`: The unique handle/identifier for the project

These variables are automatically set by Cloud and don't need to be configured manually. You can use them in your application code to access information about the current environment context.

---

## Search and Filter Environment Variables

You can search and filter the environment variables using the toolbar above the environment variables table:

- **Search**: Enter a key name or value in the search field to filter the list in real time.
- **Build / Runtime toggles**: Show only variables available at build time, only those available at runtime, or both at once.
- **System Variables toggle**: Show or hide system-managed variables. System variables are hidden by default.

---

## System Environment Variables Visibility

In addition to the [system environment variables](#system-environment-variables) documented above, the **Backend** view displays all system-provided variables alongside your user-defined ones when the **System Variables** toggle is enabled. These are variables that Medusa adds to your environment, such as database URL, Redis URL, and other relevant variables.

System variables are visually distinguished from user-defined variables with a subtle background and muted text. Because Medusa manages those:

- The edit and delete actions are not available for system variables.
- Secret system variables do not show the reveal (eye) icon.

System variables are useful to understand what variables Medusa sets for you so that you don't add them as well.

## Add Environment Variables on Cloud

To add environment variables to an environment:

<Note title="Tip">

You can also navigate to an environment's variables from the [command palette](../../command-palette/page.mdx). Press <Kbd>{getOsShortcut()}</Kbd> + <Kbd>K</Kbd>, select **Edit Variables**, then choose a project.

</Note>

1. In the [environment's dashboard](../long-lived/page.mdx#open-environment-dashboard), click **Environment variables** in the sidebar.
2. If you deployed both the Medusa backend and storefront in the environment, use the **Backend** or **Storefront** tabs to switch between managing the backend and storefront environment variables.
3. In the "Add new environment variables" section, you can add environment variables either for the backend or storefront. There are different ways you can add environment variables:
    - **Manually**:
      - Enter the key and value of the environment variable in the respective fields.
      - Use the **Sensitive** toggle to mark variables containing secrets that should be masked in the interface.
      - Use the **Build** toggle to make the variable available during build time.
      - Use the **Runtime** toggle to make the variable available during runtime (enabled by default).
      - Click the "Add another" button to add another variable.
    - **Paste `.env` format**:
      - If you copied environment variables in a `.env` file format, you can paste them directly into the "Key" field. The environment variables will be pre-filled for you.
    - **Import `.env` file**:
      - If you have a `.env` file that defines your environment variables, click the "Import .env" button to upload the file. The environment variables will be automatically extracted and added to the list.
4. Once you're done, click the "Save" button to save the environment variables.

<Note title="Important">

After adding the environment variables, you must [redeploy the environment](../long-lived/page.mdx#redeploy-environment) for the changes to take effect.

</Note>

## Edit Environment Variables on Cloud

To edit an environment variable:

<Note title="Tip">

You can also navigate to an environment's variables from the [command palette](../../command-palette/page.mdx). Press <Kbd>{getOsShortcut()}</Kbd> + <Kbd>K</Kbd>, select **Edit Variables**, then choose a project.

</Note>

1. In the [environment's dashboard](../long-lived/page.mdx#open-environment-dashboard), click **Environment variables** in the sidebar.
2. If you deployed both the Medusa backend and storefront in the environment, use the **Backend** or **Storefront** tabs to switch between managing the backend and storefront environment variables.
3. In the "Environment variables" section, find the variable you want to edit.
4. Click the <InlineIcon Icon={EllipsisHorizontal} alt="three-dots" /> icon at the variable's right side.
5. Choose "Edit" from the dropdown menu.

6. In the side window that opens, you can edit the variable's key, value, and configure its settings:
   - **Sensitive**: Whether the variable contains secrets that should be masked in the interface
   - **Build**: Whether the variable is available during build time
   - **Runtime**: Whether the variable is available during runtime
7. Once you're done, click the "Save" button.

<Note title="Important">

After editing the environment variable, you must [redeploy the environment](../long-lived/page.mdx#redeploy-environment) for the changes to take effect.

</Note>

## Export Environment Variables on Cloud

You can export an environment's variables as a `.env` file. This is useful for debugging issues that require you to have the same environment variables.

To export an environment's variables:

<Note title="Tip">

You can also navigate to an environment's variables from the [command palette](../../command-palette/page.mdx). Press <Kbd>{getOsShortcut()}</Kbd> + <Kbd>K</Kbd>, select **Edit Variables**, then choose a project.

</Note>

1. In the [environment's dashboard](../long-lived/page.mdx#open-environment-dashboard), click **Environment variables** in the sidebar.
2. If you deployed both the Medusa backend and storefront in the environment, use the **Backend** or **Storefront** tabs to switch between managing the backend and storefront environment variables.
3. In the "Environment variables" section, click on the "Export .env" button at the top right of the section.

A file download will start with the name `env.txt`, which contains the environment variables in `.env` format.

If any of the exported variables are [linked to a Vault secret](#link-environment-variables-to-vault-secrets), the dashboard asks you to confirm before it reveals their values and includes them in the file.

You can rename the file to `.env` and use it in your local development.

---

## Reveal Sensitive Environment Variables

The environment variables table masks the values of sensitive variables. To reveal a sensitive variable's value:

1. In the "Environment variables" section, find the variable you want to reveal.
2. Click the eye icon next to its masked value.
3. Confirm that you want to reveal the value.

If the variable is linked to a Vault secret, the dashboard retrieves its value from Vault.

## Link Environment Variables to Vault Secrets

<Note>

Vault integration for environment variables may not be available to all organizations yet.

</Note>

If your organization uses Vault, you can store the values of your Medusa backend's sensitive environment variables as Vault secrets, then link environment variables to them. Vault integration isn't available for storefront environment variables.

In the environment variables table, a lock icon appears next to the masked value of a variable linked to a Vault secret. Hover over the icon to see which secret the variable is linked to.

### Add a Variable Linked to a Vault Secret

To link a new environment variable to an existing Vault secret:

1. In the "Add new environment variables" section, enter the variable's key.
2. Click the lock button at the right side of the value field.
3. Search for and select the Vault secret to link the variable to.
4. Click the "Save" button.

Once you link a secret, the value field shows the secret's identifier. You can click the unlink button next to it to enter a plain value instead. The **Sensitive** toggle is enabled and locked while the variable is linked to a secret.

### Move an Existing Variable to Vault

You can move the value of an existing sensitive backend variable into a new Vault secret. To do that:

1. In the "Environment variables" section, find the variable you want to move.
2. Click the <InlineIcon Icon={EllipsisHorizontal} alt="three-dots" /> icon at the variable's right side.
3. Choose "Move to Vault" from the dropdown menu. You can also click the "Move to Vault" link in the variable's edit side window.
4. In the window that opens, fill in the following fields:
   - **Service**: (optional) The domain of the service the secret belongs to, such as `stripe.com`. The dashboard pre-fills this field if it recognizes the service from the variable's key.
   - **Name**: A slug-style name of the secret within the service. The dashboard pre-fills this field based on the variable's key.
5. Review the preview of the secret's identifier, which has the format `service/name`.
6. Submit the form.

Medusa moves the variable's value into a new Vault secret and links the variable to it.

### Edit a Variable Linked to a Vault Secret

When you [edit an environment variable](#edit-environment-variables-on-cloud) linked to a Vault secret, the side window shows the secret's identifier and version instead of the value field. To change the value, click the "Open in Vault" link to go to the secret's page in your organization's Vault settings.

The **Sensitive** toggle is always enabled for variables linked to a Vault secret, and you can't disable it.

If the variable isn't fully linked to its Vault secret yet, the value field remains editable. Medusa keeps the variable's current value unless you enter a new one.
