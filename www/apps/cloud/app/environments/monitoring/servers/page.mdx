## Server Metrics Overview

The Servers monitoring page provides real-time insights into your server infrastructure performance through four key metric cards:

## Metric Cards

### Total CPU

Displays an area chart showing your server's CPU allocation and usage:

- **Allocated CPU**: The total CPU resources allocated to your servers
- **Used CPU**: The actual CPU resources being consumed by your application
- **Visualization**: Area chart with time-based data across your selected time range

### Per Instance CPU

Shows a line chart tracking CPU performance across individual server instances:

- **Minimum CPU**: The lowest CPU percentage used across instances
- **Maximum CPU**: The highest CPU percentage used across instances  
- **Average CPU**: The mean CPU usage across all instances
- **Visualization**: Multi-line chart showing performance variation between instances

### Per Instance Memory

Displays memory utilization patterns across server instances:

- **Minimum Memory**: The lowest memory percentage used across instances
- **Maximum Memory**: The highest memory percentage used across instances
- **Average Memory**: The mean memory usage across all instances
- **Visualization**: Multi-line chart showing memory consumption patterns

### Restarts

Tracks server restart frequency and patterns:

- **Restart Count**: Number of server restarts within the selected time range
- **Restart Timing**: When restarts occurred
- **Visualization**: Bar chart showing restart frequency over time

## Accessing Server Monitoring

To access server monitoring:

1. Go to your project's dashboard in Cloud.
2. Click on the environment card you want to monitor.
3. Click the **Monitoring** tab.
4. Select **Servers** from the monitoring sidebar.

## Interpreting Server Metrics

### CPU Usage Patterns

- **Normal usage**: CPU usage should generally stay below 80% for optimal performance
- **High usage**: Sustained CPU usage above 90% may indicate the need for resource scaling
- **Usage spikes**: Occasional spikes are normal during traffic bursts or intensive operations

### Memory Consumption

- **Healthy memory usage**: Memory usage should be consistent without major leaks
- **Memory trends**: Gradual increases may indicate memory leaks that need investigation
- **Memory limits**: Approaching memory limits can cause performance degradation

### Restart Monitoring

- **Planned restarts**: Expected during deployments and updates
- **Unexpected restarts**: May indicate application crashes or infrastructure issues
- **Restart patterns**: Frequent restarts may signal underlying application or configuration problems

## Time Range and Refresh

Use the time range selector and refresh button in the top right to:

- Adjust the monitoring time window based on your subscription plan
- Get the latest server performance data
- Focus on specific time periods for detailed analysis
