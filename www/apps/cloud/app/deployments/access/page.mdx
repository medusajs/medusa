# {metadata.title}

In this guide, you'll learn how to access your Cloud [deployment](../page.mdx) for an environment.

## Access Live Deployment

You can only access a deployment of an [environment](../../environments/page.mdx) once its status is "Live". A live deployment means that your Medusa application is successfully built and is publicly accessible. You can't access previous deployments or deployments that are still in the "Building" or "Failed" status.

You can access the live deployment's Medusa Admin, send requests to its API routes, and access its storefront (if applicable) using the deployment's environment URL.

---

## Find Backend and Admin's URL

<Note>

For preview environments, refer to the [Preview Environments](../../environments/preview/page.mdx#access-deployed-preview-environment) guide to find the URL of the preview environment.

</Note>

An environment's backend URL is in the format `<subdomain>.medusajs.app`, where `<subdomain>` is the subdomain you set either when [creating its project](../../projects/page.mdx#create-a-project) or when [creating the environment](../../environments/long-lived/page.mdx#create-a-long-lived-environment-on-cloud).

You can also find the URL of a deployment's backend through the Cloud dashboard:

1. If you're in a different organization, [switch to the organization](../../organizations/page.mdx#switch-organization).
2. Click **Projects** in the sidebar and select the project that contains the environment you want to view.
3. In the project's dashboard, find the backend URL in the environment's card under the "Backend" title. You can copy the URL by clicking the copy icon next to it.

### Access the Deployment's Medusa Admin

To access the Medusa Admin of a live deployment, click on [the environment's URL](#find-backend-and-admins-url), or navigate to `<environment-url>/app`. For example, if your environment's URL is `my-project.medusajs.app`, navigate to `my-project.medusajs.app/app`.

You can then log in with your Cloud account by clicking the "Log in with Medusa Cloud" button. Medusa creates a user in the Medusa application with the same email as your Cloud account.

![Log in form of Medusa Admin](https://res.cloudinary.com/dza7lstvk/image/upload/v1767696461/Medusa%20Resources/CleanShot_2026-01-06_at_12.47.11_2x_q18pca.png)

### Can't Find the Log in with Medusa Cloud Button?

If you don't see the "Log in with Medusa Cloud" button on the Medusa Admin log in page, make sure that:

- Your Medusa application is using [Medusa v2.12.4 or later](https://github.com/medusajs/medusa/releases/tag/v2.12.4).
- The `MEDUSA_CLOUD_OAUTH_DISABLED` [environment variable](../../environments/environment-variables/page.mdx) of the environment is set to `false` or isn't set.
- If you set the [http.authMethodsPerActor](!docs!/learn/configurations/medusa-config#httpauthMethodsPerActor) configuration in `medusa-config.ts`, the `user` actor type's authentication methods include `cloud`. For example:

```ts title="medusa-config.ts"
module.exports = defineConfig({
  projectConfig: {
    http: {
      // ...
      authMethodsPerActor: {
        user: ["emailpass", "cloud"],
      },
    },
  },
})
```

After changing the environment variable, [redeploy the environment](../../environments/long-lived/page.mdx#redeploy-environment) for the change to take effect. After changing `medusa-config.ts`, push the change to the environment's branch to start a new build.

## Send Requests to the Deployed Medusa Backend

You can send requests to a live deployment's Medusa backend using the deployment's [environment URL](#find-backend-and-admins-url).

For example, to check the health of the live deployment, you can send a `GET` request to the `/health` endpoint:

```bash
curl https://my-project.medusajs.app/health
```

Where `https://my-project.medusajs.app` is the URL of the environment's Medusa backend.

---

## Access Deployment's Server through SSH

Medusa doesn't support SSH access to the server instance of a deployment. However, you can still access the server's [runtime and build logs](../../logs/page.mdx) to debug issues in your application.

If this isn't sufficient for your use case, you can contact support to discuss alternatives.

## Find Storefront URL

If you deployed a storefront alongside your Medusa backend, you can access it using the storefront URL.

By default, storefronts are deployed at the `medusajs.site` subdomain. The domain prefix is the same as the Medusa backend's subdomain. For example, if your backend is at `my-store.medusajs.app`, your storefront will be at `my-store.medusajs.site`.

You can find the storefront URL:

1. If you're in a different organization, [switch to the organization](../../organizations/page.mdx#switch-organization).
2. Click **Projects** in the sidebar and select the project that contains the environment you want to view.
3. In the project's dashboard, find the storefront URL in the environment's card under the "Storefront" title. You can copy the URL by clicking the copy icon next to it.

You can also set up a custom domain for your storefront. Learn more in the [Custom Domains](../../environments/custom-domains/page.mdx) guide.

## Manage Search Engine Indexing

Medusa doesn't control whether search engines index your deployments. Cloud doesn't add a `noindex` directive, such as an `X-Robots-Tag` response header or a `robots` meta tag, to any deployment URL. This applies to the URLs of production, long-lived, and preview environments, whether they use the Medusa-provided `medusajs.app` and `medusajs.site` subdomains or [custom domains](../../environments/custom-domains/page.mdx).

There's also no Cloud setting to enable or disable indexing. Your application's responses reach visitors and search engine crawlers unchanged, so you manage indexing in your application's code.

<Note>

To keep a page out of search results, search engines must be able to crawl it and see its `noindex` directive. If you disallow crawling a page in `robots.txt`, search engines can still index its URL when other sites link to it.

</Note>

### Prevent Indexing of Non-Production Storefronts

Search engines can discover preview and staging storefront URLs, for example, when you share them publicly. To keep these storefronts out of search results, use the `MEDUSA_CLOUD_ENVIRONMENT_TYPE` [system environment variable](../../environments/environment-variables/page.mdx#system-environment-variables) to detect the environment type in your storefront. Its value is `production` only in your project's production environment.

For example, in a Next.js storefront, such as the [Next.js Starter Storefront](!resources!/nextjs-starter), set the `robots` metadata in the root layout to add a `noindex` meta tag to all pages outside the production environment:

```tsx title="src/app/layout.tsx"
import { Metadata } from "next"

const isProduction =
  process.env.MEDUSA_CLOUD_ENVIRONMENT_TYPE === "production"

export const metadata: Metadata = {
  // ...
  robots: isProduction
    ? undefined
    : { index: false, follow: false },
}
```

After you push this change, every page of a preview or staging storefront includes the `<meta name="robots" content="noindex, nofollow">` tag, while the production storefront remains indexable.

If you use a different storefront framework, add the same `robots` meta tag or an `X-Robots-Tag: noindex` response header using that framework's equivalent mechanism, based on the value of `MEDUSA_CLOUD_ENVIRONMENT_TYPE`.

### Prevent Crawling of the Medusa Backend

Your environment's backend URL serves the Medusa Admin and the Medusa backend's API routes, which you usually don't want search engines to crawl. To ask crawlers not to crawl the backend's domain, add a [custom API route](!docs!/learn/fundamentals/api-routes) that serves a `robots.txt` file at the root of the backend's URL:

```ts title="src/api/robots.txt/route.ts"
import type {
  MedusaRequest,
  MedusaResponse,
} from "@medusajs/framework/http"

export const GET = async (
  req: MedusaRequest,
  res: MedusaResponse
) => {
  res.type("text/plain").send("User-agent: *\nDisallow: /")
}
```

After you push this change, `https://<subdomain>.medusajs.app/robots.txt` returns rules that disallow crawling the entire backend domain.

### Avoid Duplicate Content with Custom Domains

After you set up a custom domain for your production storefront, the storefront remains accessible at its Medusa-provided `medusajs.site` subdomain. To ensure search engines show your custom domain in search results, set [canonical URLs](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls) in your storefront that point to your custom domain.
