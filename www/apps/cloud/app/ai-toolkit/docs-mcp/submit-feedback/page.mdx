In this guide, you'll learn how to use the [Docs MCP server](../page.mdx) to send feedback to the Medusa team directly from your AI tool or IDE.

## What is the Submit Feedback Tool?

The `submit_medusa_feedback` tool records structured feedback for the Medusa team. Ask your AI agent to submit feedback the moment you hit a problem, without leaving your editor or writing a reproduction in an issue tracker.

The Medusa team receives the feedback immediately. Since your agent has the full context of what you were building and what went wrong, including the failing code, its report is usually more specific than one you'd write from memory later.

---

## Why This Matters

Your feedback is one of the most direct signals the Medusa team has about where Medusa falls short in real projects:

- **Documentation gaps are invisible until someone reports them.** The Medusa team can't see from the outside that the documentation failed to answer your question.
- **Friction that developers work around never gets fixed.** If you silently route around an awkward API or a confusing error, the next developer hits the same wall. Reporting it turns your workaround into a fix for everyone.
- **Real reproductions get bugs fixed faster.** Your agent can include a minimal reproduction from the code it was working on, so the Medusa team can act on the ticket instead of investigating from scratch.

Submitting feedback is always preferable to silently working around a problem.

After [connecting to the Docs MCP server](../page.mdx#connect-to-the-docs-mcp-server), ask your AI agent to submit feedback.

For example:

```bash title="Example prompt"
Submit feedback that the documentation on how to create a custom payment provider is outdated and needs to be updated.
```

Your AI agent may also offer to submit feedback on its own when it hits a documentation gap or a clearly broken API while helping you.
