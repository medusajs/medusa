In this guide, you'll learn how to use the [Docs MCP server](../page.mdx) to let your AI agent answer questions from the official Medusa documentation.

## What is the Ask Medusa Question Tool?

The `ask_medusa_question` tool searches the official Medusa documentation and returns the most relevant sections for a query, each with its source URL and content. Your AI agent answers from the current documentation instead of its training data, and cites its sources.

It's the foundational tool of the Docs MCP server: the other tools decide how to approach a task, and this one supplies the accurate details. It covers the entire documentation, from architecture and concepts to the Framework, Commerce Modules, configuration, deployment, API references, and integration guides.

---

## Who is this Useful for?

This tool is useful for:

- Developers new to Medusa who want accurate answers about concepts and APIs while they build.
- Experienced developers who want their AI agent to stop hallucinating Medusa APIs, config keys, and method signatures.
- Anyone building Medusa customizations with an AI agent, since the other guide tools direct your agent to call this tool for exact API shapes.
- Teams evaluating Medusa who want to explore what's possible without reading the whole documentation.

---

## Why Use This Tool?

Compared to browsing the documentation yourself, this tool gives you:

- **Verifiable answers.** Every result carries its source URL, so you can check your agent's claims against the source page.
- **The documentation where you're working.** Your agent retrieves what it needs mid-task, so you don't switch to a browser and paste context back in.
- **Documentation your agent can act on.** The tool returns the sections' actual content, not a summary or a link your agent can't read.
- **Fewer wrong turns.** Your agent checks an API's exact shape before using it, so you spend less time debugging code that was never going to work.

## How to Use the Ask Medusa Question Tool

After [connecting to the Docs MCP server](../page.mdx#connect-to-the-docs-mcp-server), ask your question. Your AI agent calls the tool whenever it needs Medusa knowledge, so you don't need to invoke it explicitly.

For example:

```bash title="Example prompts"
Explain the Medusa workflow system.
```

```bash title="Example prompts"
How do I create a custom API route that requires admin authentication?
```

Your agent also calls the tool mid-implementation, when it needs exact details, such as how to implement a custom module:

```bash title="Example prompts"
Create a Product Review module for Medusa.
```

### What to Expect

1. Your AI agent sends questions about Medusa to the tool.
2. The tool returns the most relevant documentation sections, each with its source URL and full Markdown content.
3. Your agent answers or writes code based on those sections, and can cite the source URLs so you can verify the answer.
4. If your agent needs more detail, it calls the tool again with a narrower question.

<Note>

If the tool can't find relevant documentation, that's a gap worth reporting. Ask your agent to [submit feedback](../submit-feedback/page.mdx) so the Medusa team can add coverage.

</Note>
