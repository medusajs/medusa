## Listen to Customer Events

To run custom logic when a customer is created, updated, or deleted, create a [subscriber](!docs!/learn/fundamentals/events-and-subscribers) that listens to the event.

For example, create the file `src/subscribers/customer-updated.ts` with the following content:

```ts title="src/subscribers/customer-updated.ts"
import type {
  SubscriberArgs,
  SubscriberConfig,
} from "@medusajs/framework"

export default async function customerUpdatedHandler({
  event: { data },
}: SubscriberArgs<{ id: string }>) {
  console.log(`Customer ${data.id} was updated`)
}

export const config: SubscriberConfig = {
  event: "customer.updated",
}
```

## Consume Customer Address Hooks

Medusa doesn't emit events when a customer address is created, updated, or deleted. Instead, consume the hooks of the address workflows. The workflows run in the Store and Admin API routes that manage customer addresses.

For example, create the file `src/workflows/hooks/addresses-created.ts` with the following content:

```ts title="src/workflows/hooks/addresses-created.ts"
import {
  createCustomerAddressesWorkflow,
} from "@medusajs/medusa/core-flows"

createCustomerAddressesWorkflow.hooks.addressesCreated(
  async ({ addresses, additional_data }, { container }) => {
    const logger = container.resolve("logger")

    logger.info(
      `Created ${addresses.length} customer address(es)`
    )
  }
)
```

The hooks receive the following data:

- `addressesCreated`: An object with the `addresses` property holding the created addresses, and the `additional_data` property holding [additional data](!docs!/learn/fundamentals/api-routes/additional-data) passed in the request.
- `addressesUpdated`: An object with the `addresses` property holding the updated addresses, and the `additional_data` property.
- `addressesDeleted`: An object with the `ids` property holding the IDs of the deleted addresses.

Learn more in the [Workflow Hooks](!docs!/learn/fundamentals/workflows/workflow-hooks) guide.

## Customer Group Operations

Medusa's customer group workflows don't emit events or expose hooks. This includes creating, updating, and deleting customer groups, and adding or removing customers in a group.

To run custom logic for these operations, create a custom workflow that runs the Medusa workflow as a step, then performs your logic. For example, the following workflow adds customers to a group, then emits a custom event that you can handle in a subscriber:

```ts title="src/workflows/add-customers-to-group.ts"
import {
  createWorkflow,
  WorkflowResponse,
} from "@medusajs/framework/workflows-sdk"
import {
  emitEventStep,
  linkCustomersToCustomerGroupWorkflow,
} from "@medusajs/medusa/core-flows"

type Input = {
  group_id: string
  customer_ids: string[]
}

export const addCustomersToGroupWorkflow = createWorkflow(
  "add-customers-to-group",
  (input: Input) => {
    linkCustomersToCustomerGroupWorkflow.runAsStep({
      input: {
        id: input.group_id,
        add: input.customer_ids,
      },
    })

    emitEventStep({
      eventName: "customer_group.customers_added",
      data: input,
    })

    return new WorkflowResponse(input)
  }
)
```

Then, execute the workflow in a [custom API route](!docs!/learn/fundamentals/api-routes) and use that route instead of Medusa's route.

## Customer Login

When a customer logs in, the `/auth/customer/{auth_provider}` API route authenticates the customer with the [Auth Module](../../auth/page.mdx) directly. It doesn't run a workflow, so Medusa doesn't emit an event or expose a hook for customer login.
