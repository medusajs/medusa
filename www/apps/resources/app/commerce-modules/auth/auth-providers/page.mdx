## What is an Auth Module Provider?

An Auth Module Provider handles authenticating customers and users, either using custom logic or by integrating a third-party service.

For example, the EmailPass Auth Module Provider authenticates a user using their email and password, whereas the Google Auth Module Provider authenticates users using their Google account.

## How to Create an Auth Module Provider?

An Auth Module Provider is a module whose service extends the `AbstractAuthModuleProvider` imported from `@medusajs/framework/utils`.

The module can have multiple auth provider services, where each is registered as a separate auth provider.

Refer to the [Create Auth Module Provider](/references/auth/provider) guide to learn how to create an Auth Module Provider.

## Configure Allowed Auth Providers of Actor Types

By default, the `user` actor type is restricted to the `emailpass` provider. All other actor types (for example, `customer`) can authenticate with any installed Auth Module Provider unless you explicitly restrict them.

To configure which auth providers are allowed for each actor type, use the [authMethodsPerActor option](!docs!/learn/configurations/medusa-config#httpauthMethodsPerActor) in Medusa's configurations:

```ts title="medusa-config.ts"
module.exports = defineConfig({
  projectConfig: {
    http: {
      authMethodsPerActor: {
        user: ["emailpass"],
        customer: ["emailpass", "google"],
      },
      // ...
    },
    // ...
  },
})
```

<Note title="Important">

When you specify the `authMethodsPerActor` configuration, it overrides the default. So, if you don't specify any providers for an actor type, users of that actor type can't authenticate with any provider.

</Note>

### Public Auth Providers for Admin Users

When an admin logs in to the Medusa Admin with a third-party provider for the first time, Medusa creates an admin user for their account without an invite. The Google and GitHub Auth Module Providers accept any Google or GitHub account, and they don't have an option to restrict the accounts that can authenticate.

So, if you allow the `user` actor type to use them, anyone with a Google or GitHub account can become an admin user of your store.

To let admin users log in with a third-party service, use one of the following instead:

- The [OIDC Auth Module Provider](../../../enterprise/sso/page.mdx) with its [allowed_email_domains option](../../../enterprise/sso/provider-options/page.mdx#allowed_email_domains), which restricts authentication to your organization's email domains.
- An identity provider that only authenticates the members of your organization, such as Okta or Microsoft Entra ID.

If you already allow the `user` actor type to use a public auth provider, remove the provider from the `user` array, then review the admin users in your store and delete the ones you don't recognize.

## Require Actor Association for Auth Providers

<Note>

This option is available since Medusa [v2.22.0](https://github.com/medusajs/medusa/releases/tag/v2.22.0).

</Note>

By default, an auth identity can authenticate as any actor type. For example, an admin user can use their credentials with the `/auth/customer/emailpass` route to create a customer account with the same email.

To only authenticate auth identities that are already associated with an actor of the requested actor type, use the [requireActorAssociation option](!docs!/learn/configurations/medusa-config#httprequireActorAssociation) in Medusa's configurations:

```ts title="medusa-config.ts"
module.exports = defineConfig({
  projectConfig: {
    http: {
      requireActorAssociation: {
        emailpass: true,
      },
      // ...
    },
    // ...
  },
})
```

With the above configuration, logging in to `/auth/user/emailpass` with a customer's credentials fails with a generic `Authentication failed` error. An auth identity is associated with an actor type when its `app_metadata` has the `{actor_type}_id` property, such as `user_id`. Learn more in the [Auth Identity and Actor Type](../auth-identity-and-actor-types/page.mdx) guide.

<Note>

This option only applies to authentication. Registering a new auth identity with the provider still works.

</Note>
