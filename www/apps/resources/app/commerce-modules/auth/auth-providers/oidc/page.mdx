# {metadata.title}

In this guide, you'll learn about the OIDC Auth Module Provider and how to install and use it in the Auth Module.

The OIDC Auth Module Provider allows you to authenticate users with any spec-compliant OpenID Connect identity provider, such as Okta, Microsoft Entra ID (Azure AD), Auth0, Keycloak, or Google Workspace. It uses a redirect-based flow: the user is redirected to the identity provider, which redirects back to your callback URL after a successful login.

## Register the OIDC Auth Module Provider

To use the OIDC Auth Module Provider, add it to the array of providers passed to the Auth Module in your `medusa-config.ts`:

```ts title="medusa-config.ts"
import { Modules, ContainerRegistrationKeys } from "@medusajs/framework/utils"

// ...

module.exports = defineConfig({
  // ...
  modules: [
    {
      resolve: "@medusajs/medusa/auth",
      dependencies: [Modules.CACHE, ContainerRegistrationKeys.LOGGER],
      options: {
        providers: [
          // other providers...
          {
            resolve: "@medusajs/medusa/auth-oidc",
            id: "okta",
            options: {
              issuer: process.env.OIDC_ISSUER,
              client_id: process.env.OIDC_CLIENT_ID,
              client_secret: process.env.OIDC_CLIENT_SECRET,
              callback_url: process.env.OIDC_CALLBACK_URL,
            },
          },
        ],
      },
    },
  ],
})
```

The `id` you give the provider (for example, `okta`) is used in authentication routes, such as `POST /auth/user/okta` and `GET /auth/user/okta/callback`.

You can register multiple instances of the OIDC provider with different IDs to support several identity providers simultaneously.

### Environment Variables

Make sure to add the necessary environment variables for the above options in `.env`:

```plain
OIDC_ISSUER=<YOUR_ISSUER_URL>
OIDC_CLIENT_ID=<YOUR_CLIENT_ID>
OIDC_CLIENT_SECRET=<YOUR_CLIENT_SECRET>
OIDC_CALLBACK_URL=<YOUR_CALLBACK_URL>
```

## Authentication Flow

The OIDC provider uses a redirect-based flow:

1. The frontend calls `POST /auth/{actor_type}/{provider_id}` (for example, `POST /auth/user/okta`). Medusa redirects to the identity provider's authorization endpoint.
2. The user authenticates with the identity provider.
3. The identity provider redirects to the configured `callback_url` with an authorization code.
4. The frontend calls `GET /auth/{actor_type}/{provider_id}/callback` with the query parameters received from the identity provider. Medusa exchanges the code for tokens, validates the ID token, and returns a JWT.

---

## Provisioning Admin Users

For redirect-based providers, after the callback, the returned JWT does not yet have an actor (user or customer) linked to it. You must call the provision endpoint to link or create the actor before the token can be used for admin operations.

Use the JS SDK's `auth.createUser` method:

```ts
const token = await sdk.auth.callback("user", "okta", queryParams)
await sdk.auth.createUser("okta", { Authorization: `Bearer ${token}` })
await sdk.auth.refresh()
```

This endpoint checks whether an admin user with the identity-provider-verified email already exists:

- If a user exists, it is linked to the auth identity.
- If no user exists, a new admin user is created from the claims returned by the identity provider.

---

## Override Callback URL During Authentication

In many cases, you may have different callback URLs for different actor types. For example, you may redirect admin users to a different URL than customers.

The [Authenticate or Login API Route](../../authentication-route/page.mdx#login-route) accepts a `callback_url` body parameter to override the provider's `callback_url` option. You can restrict which URLs are allowed using the `allowed_callback_urls` option.

---

## Multiple OIDC Providers

You can register the OIDC provider multiple times with different IDs to connect several identity providers:

```ts title="medusa-config.ts"
providers: [
  {
    resolve: "@medusajs/medusa/auth-oidc",
    id: "okta",
    options: {
      issuer: process.env.OKTA_ISSUER,
      client_id: process.env.OKTA_CLIENT_ID,
      client_secret: process.env.OKTA_CLIENT_SECRET,
      callback_url: process.env.OKTA_CALLBACK_URL,
      display_name: "Okta",
    },
  },
  {
    resolve: "@medusajs/medusa/auth-oidc",
    id: "entra",
    options: {
      issuer: process.env.ENTRA_ISSUER,
      client_id: process.env.ENTRA_CLIENT_ID,
      client_secret: process.env.ENTRA_CLIENT_SECRET,
      callback_url: process.env.ENTRA_CALLBACK_URL,
      display_name: "Microsoft Entra ID",
    },
  },
],
```
