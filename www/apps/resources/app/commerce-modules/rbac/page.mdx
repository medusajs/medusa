# {metadata.title}

In this section of the documentation, you will find resources to learn more about the RBAC Module and how to use it in your application.

<Note title="Looking for no-code docs?">

Refer to the [Medusa Admin User Guide](!user-guide!/settings/rbac) to learn how to manage roles and permissions using the dashboard.

</Note>

Medusa has role-based access control (RBAC) features available out-of-the-box through the RBAC Module. A [module](!docs!/learn/fundamentals/modules) is a standalone package that provides features for a single domain. Each of Medusa's commerce features are placed in Commerce Modules, such as this RBAC Module.

<Note>

Learn more about why modules are isolated in [this documentation](!docs!/learn/fundamentals/modules/isolation).

</Note>

## RBAC Features

- [Roles and Policies](./concepts/page.mdx): Create and manage roles with specific permissions for users and teams.
- [Permission System](./concepts/page.mdx#permissions): Fine-grained permission control using resource:operation format with wildcard support.
- [Permission Guards](./concepts/page.mdx#permission-guards): UI components and hooks for conditional rendering based on user permissions.
- [Policy Inheritance](./concepts/page.mdx#policy-inheritance): Hierarchical role structures with inherited permissions.
- [Runtime Policy Management](./concepts/page.mdx#runtime-policies): Create and modify policies dynamically at runtime.

## How to Use the RBAC Module

In your Medusa application, you build flows around Commerce Modules. A flow is built as a [Workflow](!docs!/learn/fundamentals/workflows), which is a special function composed of a series of steps that guarantees data consistency and reliable roll-back mechanism. 

You can build custom workflows and steps. You can also re-use Medusa's workflows and steps, which are provided by the `@medusajs/medusa/core-flows` package.

For example:

]

```ts title="src/workflows/create-role.ts" highlights={highlights}
import { 
  createWorkflow, 
  WorkflowResponse,
  createStep,
  StepResponse,
} from "@medusajs/framework/workflows-sdk"
import { Modules } from "@medusajs/framework/utils"

const createRoleStep = createStep(
  "create-role",
  async ({ name, description }, { container }) => {
    const rbacModuleService = container.resolve(Modules.RBAC)

    const role = await rbacModuleService.createRoles({
      name,
      description,
    })

    return new StepResponse({ role }, role.id)
  },
  async (roleId, { container }) => {
    const rbacModuleService = container.resolve(Modules.RBAC)

    await rbacModuleService.deleteRoles([roleId])
  }
)

export const createRoleWorkflow = createWorkflow(
  "create-role",
  (input) => {
    const { role } = createRoleStep(input)

    return new WorkflowResponse({
      role,
    })
  }
)
```

You can then execute the workflow in your custom API routes, scheduled jobs, or subscribers:

export async function POST(
  req: MedusaRequest,
  res: MedusaResponse

  const { result } = await createRoleWorkflow(req.scope)

      input: {
        name: "Editor",
        description: "Can edit content",
      },
    })

}

import { MedusaContainer } from "@medusajs/framework/types"
import { Modules } from "@medusajs/framework/utils"

export default async function cleanupRolesJob(
  container: MedusaContainer
) {
  const rbacModuleService = container.resolve(Modules.RBAC)

  // Remove unused roles
  const unusedRoles = await rbacModuleService.listRoles({
    // Custom logic to find unused roles
  })

  if (unusedRoles.length > 0) {
    await rbacModuleService.deleteRoles(
      unusedRoles.map((role) => role.id)
    )
  }
}

export const config = {
  name: "cleanup-roles",
  schedule: `0 2 * * 0`, // Weekly at 2 AM on Sunday
}
