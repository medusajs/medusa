# {metadata.title}

Role-Based Access Control (RBAC) allows you to control what actions users can perform in your Medusa application by assigning them roles with specific policies.

<Note>

RBAC is available as an experimental feature under the `rbac` feature flag. Learn how to enable it in the [Feature Flags guide](!docs!/learn/debugging-and-testing/feature-flags).

</Note>

## Overview

RBAC in Medusa is built around three core concepts:

- **Policies**: Define specific permissions for actions on resources (e.g., "create product", "read order")
- **Roles**: Collections of policies that can be assigned to users
- **Users**: Admin users who are assigned roles to control their access

### Policies

A policy defines permission for a specific operation on a resource. Each policy has:

- **Key**: A unique identifier
- **Resource**: The type of entity (e.g., `product`, `order`, `customer`)
- **Operation**: The action allowed (e.g., `create`, `read`, `update`, `delete`)
- **Name**: A human-readable display name
- **Description**: Optional description of what the policy allows

### Roles

A role is a collection of policies that can be assigned to users. Roles allow you to:

- Group related permissions together
- Assign multiple policies at once to users
- Create hierarchical permission structures
- Manage user access at scale

### Permission Checking

The RBAC system automatically validates user permissions for:

- API route access
- Admin dashboard actions
- Workflow step execution
- Resource operations

## Use RBAC in Custom Code

You can check permissions programmatically in your custom workflows and API routes.

### Check Permissions in Workflows

Use the `hasPermission` function to check if a user has permission for specific actions:

```ts title="src/workflows/check-permission.ts"
import { 
  createStep,
  StepResponse,
} from "@medusajs/framework/workflows-sdk"
import { hasPermission, MedusaError } from "@medusajs/framework/utils"

const checkUserPermissionStep = createStep(
  "check-user-permission",
  async ({ userId, resource, operation }, { container }) => {
    // Get user's role IDs
    const query = container.resolve(ContainerRegistrationKeys.QUERY)
    const { data: users } = await query.graph({
      entity: "user",
      fields: ["rbac_roles.id"],
      filters: { id: userId },
    })

    const roleIds = users?.[0]?.rbac_roles?.map((r) => r.id) ?? []

    // Check permission
    const allowed = await hasPermission({
      roles: roleIds,
      actions: [{ resource, operation }],
      container,
    })

    if (!allowed) {
      throw new MedusaError(
        MedusaError.Types.FORBIDDEN,
        `You don't have permission to ${operation} ${resource}`
      )
    }

    return new StepResponse({ allowed: true })
  }
)
```

### Protect API Routes

API routes can be protected using policies in middleware configuration:

```ts title="src/api/custom/middlewares.ts"
import { 
  validateAndTransformQuery,
  createFindParams,
} from "@medusajs/framework"
import { MiddlewareRoute } from "@medusajs/framework/http"
import { PolicyOperation } from "@medusajs/framework/utils"

export const customRoutesMiddlewares: MiddlewareRoute[] = [
  {
    method: ["GET"],
    matcher: "/custom/protected-data",
    middlewares: [],
    policies: [
      { 
        resource: "custom_resource", 
        operation: PolicyOperation.read, 
      },
    ],
  },
]
```

## Custom Policies

You can define custom policies for your application using the `definePolicies` utility:

```ts title="src/policies/custom-policies.ts"
import { definePolicies } from "@medusajs/framework/utils"

export const customPolicies = definePolicies([
  {
    key: "custom:read-analytics",
    resource: "analytics",
    operation: "read",
    name: "Read Analytics Data",
    description: "Allow reading analytics data",
  },
  {
    key: "custom:manage-settings",
    resource: "settings",
    operation: "manage",
    name: "Manage Settings",
    description: "Allow managing application settings",
  },
])
```

Then register your policies in your module or main application:

```ts title="src/index.ts"
import { customPolicies } from "./policies/custom-policies"

// Register policies during application startup
export default async function () {
  // Your application initialization code
  return customPolicies
}
```

## Best Practices

### Role Design

- **Create role hierarchies**: Design roles that build upon each other (e.g., "Viewer" → "Editor" → "Admin")
- **Use descriptive names**: Give roles clear, descriptive names that reflect their purpose
- **Group by function**: Create roles based on job functions rather than individual permissions

### Policy Management

- **Be specific**: Create policies for specific actions rather than broad "admin" permissions
- **Use consistent naming**: Follow a consistent naming convention for policy keys
- **Document policies**: Add clear descriptions to explain what each policy allows

### Security Considerations

- **Principle of least privilege**: Give users only the minimum permissions they need
- **Regular audits**: Periodically review user roles and permissions
- **Test permission changes**: Always test permission changes in a non-production environment
