In this guide, you'll learn how to show or hide content in your admin customizations based on the logged-in admin user's permissions and roles.

## Permission Utilities Overview

In your [admin customizations](!docs!/learn/fundamentals/admin), such as widgets and UI routes, you can use the following utilities to check the admin user's permissions and roles:

- `PermissionGuard`: A component that renders its children only if the admin user has the specified permissions.
- `RoleGuard`: A component that renders its children only if the admin user has the specified roles.
- `usePermissions`: A hook that returns functions to check the admin user's permissions and roles.

A permission is a string of the format `resource:operation`, such as `customer:create`. It matches the [policies](../concepts/page.mdx#policy) of the admin user's roles, including wildcard policies.

When the RBAC Module isn't installed, these utilities allow all permissions and roles.

<Note title="Tip">

These utilities only change what the Medusa Admin dashboard displays. The Medusa backend still checks the admin user's permissions when the dashboard sends requests to API routes. Learn how to guard your custom API routes in the [Protect API Routes](../protect-routes/page.mdx) guide.

</Note>

## PermissionGuard Component

The `PermissionGuard` component renders its children only if the admin user has the specified permissions.

For example, to show a button only to admin users who can create customers:

export const guardHighlights = [
  ["8", "PermissionGuard", "Render the button only if the user can create customers."],
]

```tsx title="src/admin/widgets/customer-actions.tsx" highlights={guardHighlights}
import { defineWidgetConfig } from "@medusajs/admin-sdk"
import { Button, Container } from "@medusajs/ui"
import { PermissionGuard } from "@medusajs/dashboard/hooks"

const CustomerActionsWidget = () => {
  return (
    <Container>
      <PermissionGuard resource="customer" operation="create">
        <Button>Create Customer</Button>
      </PermissionGuard>
    </Container>
  )
}

export const config = defineWidgetConfig({
  zone: "customer.list.before",
})

export default CustomerActionsWidget
```

For example, to require multiple permissions and show a message if the admin user doesn't have them:

```tsx
<PermissionGuard
  permissions={["customer:read", "order:read"]}
  requireAll
  fallback={<Text>You can't view customer orders.</Text>}
>
  <CustomerOrders />
</PermissionGuard>
```

## RoleGuard Component

The `RoleGuard` component renders its children only if the admin user has the specified roles, by their names. It's useful when checking a role is more practical than listing its permissions.

For example:

```tsx
import { RoleGuard } from "@medusajs/dashboard/hooks"

// ...

<RoleGuard role="Billing">
  <BillingSection />
</RoleGuard>
```

By default, an admin user has a role if their permissions cover all the policies of that role, even if the role isn't assigned to them. For example, a super admin passes every role check. To require that the role is assigned to the admin user, set the `match` prop to `assigned`:

```tsx
<RoleGuard role="Auditor" match="assigned">
  <AuditLogExport />
</RoleGuard>
```

## usePermissions Hook

The `usePermissions` hook returns functions to check the admin user's permissions and roles in your component's logic.

For example:

export const hookHighlights = [
  ["9", "usePermissions", "Retrieve the permission check functions."],
  ["15", "can", "Check whether the user can delete customers."],
]

```tsx title="src/admin/widgets/customer-delete.tsx" highlights={hookHighlights}
import { defineWidgetConfig } from "@medusajs/admin-sdk"
import { Button, Container } from "@medusajs/ui"
import { usePermissions } from "@medusajs/dashboard/hooks"

const CustomerDeleteWidget = () => {
  const {
    can,
    isLoading,
  } = usePermissions()

  if (isLoading) {
    return null
  }

  if (!can("customer", "delete")) {
    return null
  }

  return (
    <Container>
      <Button variant="danger">Delete Customers</Button>
    </Container>
  )
}

export const config = defineWidgetConfig({
  zone: "customer.list.before",
})

export default CustomerDeleteWidget
```
