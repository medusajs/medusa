## What is a Search Index Definition?

A search index definition declares one index: the entity it indexes, the fields the search engine holds, and how to fill it. The [Search Module](../page.mdx) owns everything around it, including creating the physical index, batching writes, and rebuilding the index when the definition changes. Refer to the [Reindexing and Migrations guide](../reindexing/page.mdx) for how it does that.

Define an index with `defineSearchIndex` in a file under the `src/search` directory of your Medusa application or plugin. Medusa loads every file in that directory before the application boots, and each file registers its indexes on import.

For example, create the file `src/search/product.ts` with the following content:

export const highlights = [
  ["7", "name", "The unique index name a query resolves against."],
  ["8", "entity", "The Query entity used to hydrate other fields."],
  ["9", "fields", "The fields the search engine holds."],
  ["13", "seed", "Yields the documents that fill the index."],
]

```ts title="src/search/product.ts" highlights={highlights}
import {
  defineSearchIndex,
  search,
} from "@medusajs/framework/utils"

export const productIndex = defineSearchIndex({
  name: "product",
  entity: "product",
  fields: search.define({
    id: search.keyword().filterable(),
    title: search.text().searchable(),
  }),
  async *seed({ container }) {
    const { data } = await container.query.graph({
      entity: "product",
      fields: ["id", "title"],
    })

    yield data
  },
})
```

If you're using the [PostgreSQL Search Module Provider](../providers/postgres/page.mdx) or a provider that makes changes to the database, you must also run the migrations that create the necessary tables:

```bash npx2yarn
npx medusa db:migrate
```

## Fill the Index with `seed`

`seed` is an async generator that yields batches of documents. The Search Module runs it in the following cases:

1. A migration created the index and nothing has filled it yet.
2. The index exists but holds no documents, such as after an engine restart wiped it.
3. A migration built a new index for a changed schema, which the module fills and then swaps in.
4. The previous run didn't complete, so the module resumes it where it stopped.
5. You rebuild the index on demand with the Search Module's `reindex` method.

The first four cases run when your application starts. Refer to the [Reindexing and Migrations guide](../reindexing/page.mdx) to learn how the module plans and runs each of them.

`seed` receives an object parameter with the following properties:

Yield in batches using the `yield` keyword so the module writes to the engine as it goes, rather than holding the entire index in memory.

For example, the following `seed` reads every product in batches of `500` and yields them to the index:

```ts title="src/search/product.ts"
async *seed({ container, filters }) {
  const limit = 500
  let offset = 0

  while (true) {
    const { data } = await container.query.graph({
      entity: "product",
      fields: ["id", "title", "handle", "status"],
      filters,
      pagination: { skip: offset, take: limit },
    })

    if (!data.length) {
      break
    }

    yield data

    offset += limit
  }
}
```

## Keep an Index Up-to-Date

If you omit `events` and `consume`, the Search Module only fills an index in the [cases listed for `seed`](#fill-the-index-with-seed). So the index holds whatever the last run produced until something triggers another one.

<Note>

A restart doesn't refill an index that already has documents, unless the provider's indexes don't outlive the process. For example, a provider that holds indexes in memory always leaves an empty index after a restart, so the module refills it.

</Note>

To ensure your index is always up-to-date, you must add the following to your index definition:

- `events`: an array of event names that change the data the index holds. Medusa subscribes to them and calls `consume` for each one.
    - See the [Events Reference](/references/events) for the full list of events Medusa emits and their payloads. You can also use custom events that you emit.
- `consume`: a function that turns an event into document writes.

`consume` receives two parameters:

<Note>

`context` holds `container` and `index` only. Unlike [`seed`](#fill-the-index-with-seed), it carries no `filters` or `last_key`, since an event changes specific documents rather than filling the whole index.

</Note>

It returns an array of write instructions, each of which is one of the following:

- `{ action: "upsert", documents }`: writes the documents into the index.
- `{ action: "delete", filters }`: removes every document matching the filters.

For example:

```ts title="src/search/product.ts"
import {
  defineSearchIndex,
  search,
} from "@medusajs/framework/utils"

const fields = ["id", "title", "handle", "status"]

export const productIndex = defineSearchIndex({
  name: "product",
  entity: "product",
  fields: search.define({
    id: search.keyword().filterable(),
    title: search.text().searchable(),
    handle: search.keyword().filterable(),
    status: search.keyword().filterable().facetable(),
  }),
  events: [
    "product.created",
    "product.updated",
    "product.deleted",
  ],
  async consume(event, { container }) {
    if (event.name === "product.deleted") {
      return [{
        action: "delete",
        filters: { id: [event.data.id] },
      }]
    }

    const { data } = await container.query.graph({
      entity: "product",
      fields,
      filters: { id: event.data.id },
    })

    return [{ action: "upsert", documents: data }]
  },
  async *seed({ container }) {
    const { data } = await container.query.graph({
      entity: "product",
      fields,
    })

    yield data
  },
})
```

In this example, when a product is created or updated, the `consume` function reads the product's current data and upserts it into the index. When a product is deleted, it removes the document from the index.

## Point an Index at a Specific Provider

If you're using multiple [Search Module Providers](../providers/page.mdx), set the `provider` property to the ID of a registered provider. 

For example, you can keep a high-traffic index on a dedicated engine while quieter indexes stay on PostgreSQL.

```ts title="src/search/product.ts"
export const productIndex = defineSearchIndex({
  name: "product",
  entity: "product",
  provider: "search-postgres",
  // ...
})
```

When you omit it, the index uses the module's `default_provider`.
