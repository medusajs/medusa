# {metadata.title}

This is a reference to the `medusaIntegrationTestRunner` function provided by the `@medusajs/test-utils` package.

## Example

```ts
import { medusaIntegrationTestRunner } from "@medusajs/test-utils"

medusaIntegrationTestRunner({
  testSuite: ({ api, getContainer }) => {
    // TODO write tests...
  },
})
```

## Database Baseline

The test runner takes a PostgreSQL snapshot of the database and
restores it before each test, so that data created in one test
doesn't leak into the next one.

Use the `seedBaseline` option to seed the data shared by every test
in the file. The runner runs it once after the Medusa application
starts, then snapshots the result:

```ts
medusaIntegrationTestRunner({
  seedBaseline: async ({ api, getContainer }) => {
    // seed data shared by the whole file
  },
  testSuite: ({ api }) => {
    describe("products", () => {
      it("lists the seeded products", async () => {
        // starts from the seedBaseline state
      })
    })

    describe("carts", () => {
      it("also starts from the same state", async () => {
        // ...
      })
    })
  },
})
```

<Note>

The `seedBaseline` option is available since Medusa [v2.18.1](https://github.com/medusajs/medusa/releases/tag/v2.18.1).

</Note>

When you pass `seedBaseline`, the runner restores the baseline before
every test, including the first one. Data that a nested `describe`
block creates in its own `beforeAll` hook is not part of the baseline,
so the runner rolls it back before that block's tests run. Move data
that all tests need into `seedBaseline`, and keep data that only one
test needs in a `beforeEach` hook or in the test itself.

If a nested `describe` block needs its own baseline, call
`utils.freezeDatabaseBaseline()` at the end of its `beforeAll` hook:

```ts
describe("orders", () => {
  beforeAll(async () => {
    // create the orders this block needs
    await utils.freezeDatabaseBaseline()
  })

  it("starts from the orders baseline", async () => {
    // ...
  })
})
```

<Note type="warning">

If you don't pass `seedBaseline`, the runner keeps its previous
behavior and snapshots the database right before the first test runs.
The snapshot then includes whatever the first nested `describe` block
seeded in its `beforeAll` hook, and later sibling blocks lose their
own setup. Pass `seedBaseline` or call `utils.freezeDatabaseBaseline()`
to avoid this.

</Note>
