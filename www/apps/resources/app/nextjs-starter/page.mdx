# {metadata.title}

<Note>

Since Medusa v2.14.0, the Next.js Starter storefront is part of a monorepo with the Medusa application. The [standalone Next.js Starter Storefront](https://github.com/medusajs/nextjs-starter-medusa) is now deprecated.

</Note>

The Medusa application is made up of a Node.js server and an admin dashboard. The storefront is hosted separately from the Medusa application. You have the flexibility to choose the frontend tech stack that you and your team are proficient in, and implement unique design systems and user experience.

The Next.js Starter Storefront is a good place to start building your storefront. It provides rich commerce features and a sleek design. Developers and businesses can use it as-is or build on top of it to tailor it for the business's unique use case, design, and customer experience.

<Note>

This guide helps technical users set up the Next.js Start storefront. If you're not a technical user, refer your technical team to this documentation instead.

</Note>

The Blank DTC starter on Cloud includes the Medusa application and the Next.js Starter storefront. To create a project from it, follow the [Create Your First Project](!cloud!/first-project#option-1-choose-a-starter) guide.

Cloud clones the starter into a GitHub repository in your account or organization, then deploys both the Medusa application and the storefront. It also sets the storefront's backend URL, publishable API key, and CORS settings for every environment. Learn more in the [Storefront Deployment](!cloud!/storefront) guide.

Then, to customize the storefront, set up the project on your machine by following the [Set Up Medusa Locally](!cloud!/setup-locally) guide. The Medusa backend is in the `apps/backend` directory, and the Next.js Starter storefront is in the `apps/storefront` directory. Locally, the storefront runs at `http://localhost:8000`.

### Approach 2: Add to an Existing Project

If you already have a Medusa monorepo installed and want to add the Next.js Starter storefront to it, follow these steps.

1. From the root of your monorepo, clone the [DTC Starter](https://github.com/medusajs/dtc-starter) into a temporary directory to extract the storefront:

```bash
git clone https://github.com/medusajs/dtc-starter.git --depth=1 dtc-temp
```

2. Copy the storefront into your project's `apps` directory, then remove the temporary clone:

```bash
cp -r dtc-temp/apps/storefront apps/storefront
rm -rf dtc-temp
```

3. Make sure your workspace configuration includes the `apps/storefront` directory. If your `pnpm-workspace.yaml` or the `workspaces` field in `package.json` already uses a glob like `apps/*`, no change is needed. Otherwise, add it explicitly:

```yaml title="pnpm-workspace.yaml"
packages:
  - 'apps/*'
```

4. From the monorepo root, install the dependencies:

```bash npm2yarn
npm install
```

5. Create the storefront's environment file from its template:

```bash
cp apps/storefront/.env.template apps/storefront/.env.local
```

6. In `apps/storefront/.env.local`, set the URL of your Medusa backend and your publishable API key. You can retrieve the publishable API key from the Medusa Admin dashboard by going to **Settings** > **Publishable API Keys**:

```bash title="apps/storefront/.env.local"
NEXT_PUBLIC_MEDUSA_BACKEND_URL=http://localhost:9000
NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY=pk_123...
```

7. While the Medusa application is running, start the Next.js Starter storefront from the `apps/storefront` directory:

```bash npm2yarn
cd apps/storefront
npm run dev
```

Your Next.js Starter storefront is now running at `http://localhost:8000`.

8. To deploy the storefront to Cloud, commit and push the `apps/storefront` directory to your project's repository. Then, [add the storefront to your Cloud project](!cloud!/projects#add-storefront-to-existing-project) with `apps/storefront` as its root directory. Cloud sets the storefront's backend URL and publishable API key, so you don't add `NEXT_PUBLIC_MEDUSA_BACKEND_URL` or `NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY` to its environment variables.

## Payment Providers

### Stripe Integration

The Next.js Starter storefront is compatible with Medusa's Stripe Module Provider.

<Prerequisites items={[
  {
    text: "Stripe Module Provider installed in the Medusa application.",
    link: "../commerce-modules/payment/payment-provider/stripe/page.mdx"
  },
]} />

The storefront reads your Stripe publishable key from the `NEXT_PUBLIC_STRIPE_KEY` environment variable. You can retrieve the key from your [Stripe dashboard](https://dashboard.stripe.com/) by going to Developers → API Keys.

On Cloud, add `NEXT_PUBLIC_STRIPE_KEY` in the environment's **Storefront** variables, and enable its **Build** toggle, since Next.js includes it in the storefront's build. Then, redeploy the environment. Learn more in the [Environment Variables](!cloud!/environments/environment-variables) Cloud guide.

Locally, set the variable in `apps/storefront/.env.local`:

```bash
NEXT_PUBLIC_STRIPE_KEY=<YOUR_PUBLISHABLE_KEY>
```

Where `<YOUR_PUBLISHABLE_KEY>` is your Stripe publishable key. Then, restart the Next.js Starter storefront. You can now use Stripe during checkout.

<Note title="Tip">

Refer to [this guide](./guides/customize-stripe/page.mdx) to learn how to customize the Stripe integration and components.

</Note>

## Change Medusa Application URL

The Next.js Starter storefront reads the URL of the Medusa application from the `MEDUSA_BACKEND_URL` environment variable.

On Cloud, Medusa sets this variable to the URL of the environment's Medusa application, so you don't need to set it. Learn more in the [Storefront Deployment](!cloud!/storefront#injected-environment-variables) guide.

Locally, the Medusa application runs at `http://localhost:9000` by default. To change the URL of the Medusa application in the storefront, set the `MEDUSA_BACKEND_URL` environment variable in `apps/storefront/.env.local`:

```bash
MEDUSA_BACKEND_URL=https://example.com
```

## Change Medusa Publishable API Key

All requests made from a storefront must pass a publishable API key in the request's header. This API key is created in the Medusa application.

On Cloud, Medusa sets the `NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY` environment variable to a publishable API key of the environment's Medusa application, so you don't need to set it.

Locally, if you change your Medusa application or its database, or you lose the publishable API key you had before, change the `NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY` environment variable in `apps/storefront/.env.local` to the new publishable API key:

```bash
NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY=pk_123...
```
