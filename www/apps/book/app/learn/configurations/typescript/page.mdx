# {metadata.title}

In this chapter, you'll learn how to configure your Medusa application or plugin to use TypeScript 6 or TypeScript 7.

## TypeScript Version Support

Medusa applications and plugins use TypeScript 5 by default. You can upgrade them to TypeScript 6 or TypeScript 7, but you need to update your `tsconfig.json` because TypeScript 6 changed some default compiler options.

<Note>

Support for TypeScript 7 is available since Medusa [v2.22.4](https://github.com/medusajs/medusa/releases/tag/v2.22.4).

</Note>

---

## Step 1: Install TypeScript

To use TypeScript 6, install it as a development dependency:

```bash npm2yarn
npm install --save-dev typescript@^6
```

To use TypeScript 7, install it along with the `@typescript/typescript6` package:

```bash npm2yarn
npm install --save-dev typescript@^7 @typescript/typescript6
```

TypeScript 7 doesn't expose a compiler API. So, Medusa uses `@typescript/typescript6` to load TypeScript files, such as `medusa-config.ts`, when you run `medusa` commands. If the package isn't installed, the Medusa CLI shows an error asking you to install it.

---

## Step 2: Update `tsconfig.json`

Next, update the `compilerOptions` in your application's or plugin's `tsconfig.json`:

```json title="tsconfig.json"
{
  "compilerOptions": {
    // other options...
    "strict": false,
    "types": ["*"]
  }
}
```

TypeScript 6 changed the defaults of these options:

- `strict` is now `true` by default. Setting it to `false` keeps the TypeScript 5 behavior. Otherwise, your build may report new errors, such as implicit `any` types.
- `types` is now `[]` by default, so TypeScript no longer loads the type packages in `node_modules/@types` automatically. Setting it to `["*"]` keeps the TypeScript 5 behavior. Otherwise, your build may report errors like `Cannot find name 'describe'` in your test files.

### Remove `baseUrl`

TypeScript 6 deprecates the `baseUrl` option, and TypeScript 7 removes it. If your `tsconfig.json` or `src/admin/tsconfig.json` sets `baseUrl`, remove it and make sure the paths in `paths` are relative to the `tsconfig.json` file:

export const baseUrlHighlights = [
  ["4", "\"./src/*\"", "Start the path with `./`."]
]

```json title="tsconfig.json" highlights={baseUrlHighlights}
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}
```

Learn more about configuring aliases in the [Type Aliases](../ts-aliases/page.mdx) chapter.

---

## Step 3: Test the Configurations

To verify that your application or plugin builds with the new TypeScript version, run the `build` command:

```bash npm2yarn
npm run build
```

If the build succeeds without new type errors, your project is ready to use the new TypeScript version.
