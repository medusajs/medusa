# {metadata.title}

Learn how to implement Role-Based Access Control (RBAC) in your Medusa Admin extensions to provide secure, permission-based access to different features.

## What is RBAC?

Role-Based Access Control (RBAC) is a security model that controls access to resources based on user roles and permissions. In Medusa, RBAC allows you to:

- Define granular permissions for different resources and operations
- Create roles that group related permissions together
- Assign roles to admin users to control their access
- Build permission-aware admin UI components

## Enabling RBAC

RBAC is controlled by a feature flag. Enable it in your `medusa-config.ts`:

```ts title="medusa-config.ts"
import { defineConfig } from "@medusajs/framework"

export default defineConfig({
  // ... other configurations
  featureFlags: {
    rbac: true,
  },
})
```

<Note>

RBAC functionality requires the `rbac` feature flag to be enabled. Without it, permission checks will return `true` for all operations.

</Note>

## Permission-Based UI Components

Medusa provides React components and hooks for building permission-aware admin UI.

### PermissionGuard Component

Use `PermissionGuard` to conditionally render UI based on user permissions:

```tsx title="src/admin/widgets/product-actions.tsx"
import { PermissionGuard } from "@medusajs/dashboard"
import { Button } from "@medusajs/ui"

export default function ProductActions() {
  return (
    <div className="flex gap-2">
      <PermissionGuard permissions={["product:create"]}>
        <Button>Create Product</Button>
      </PermissionGuard>
      
      <PermissionGuard permissions={["product:update"]}>
        <Button>Edit Product</Button>
      </PermissionGuard>
      
      <PermissionGuard permissions={["product:delete"]}>
        <Button variant="danger">Delete Product</Button>
      </PermissionGuard>
    </div>
  )
}
```

### Permission Hooks

For more complex logic, use the `usePermissions` hook:

```tsx title="src/admin/widgets/dynamic-menu.tsx"
import { usePermissions } from "@medusajs/dashboard"
import { Button, DropdownMenu } from "@medusajs/ui"

export default function DynamicMenu() {
  const { can, hasAnyPermission } = usePermissions()
  
  const canManageProducts = hasAnyPermission([
    "product:create", 
    "product:update", 
    "product:delete",
  ])
  
  if (!canManageProducts) {
    return null
  }
  
  return (
    <DropdownMenu>
      <DropdownMenu.Trigger asChild>
        <Button>Actions</Button>
      </DropdownMenu.Trigger>
      <DropdownMenu.Content>
        {can("product", "create") && (
          <DropdownMenu.Item>Create Product</DropdownMenu.Item>
        )}
        {can("product", "update") && (
          <DropdownMenu.Item>Edit Product</DropdownMenu.Item>
        )}
        {can("product", "delete") && (
          <DropdownMenu.Item>Delete Product</DropdownMenu.Item>
        )}
      </DropdownMenu.Content>
    </DropdownMenu>
  )
}
```

## Permission Format

Permissions follow the format `resource:operation`:

- **Resources**: Core commerce entities like `product`, `customer`, `order`, `inventory`
- **Operations**: Actions like `read`, `create`, `update`, `delete`, or `*` (wildcard)

### Common Permission Examples

```tsx
// Resource-specific permissions
"product:read"     // View products
"product:create"   // Create products  
"product:update"   // Edit products
"product:delete"   // Delete products
"product:*"        // All product operations

// Cross-resource permissions
"*:read"          // Read all resources
"*:*"             // Super admin access

// Custom permissions for extensions
"reports:generate"   // Generate custom reports
"analytics:export"   // Export analytics data
```

### Wildcard Support

The permission system automatically handles wildcards:

```tsx
// User with "product:*" permission automatically gets:
// - product:read
// - product:create
// - product:update
// - product:delete

// User with "*:read" can read any resource
hasPermission("product:read")   // ✅ true
hasPermission("customer:read")  // ✅ true 
hasPermission("order:read")     // ✅ true
```

## Working with Policies

Policies define the specific permissions available in your system. You can define custom policies for your admin extensions.

### Code-Defined Policies

Define policies in your module or plugin:

```ts title="src/modules/analytics/index.ts"
import { definePolicies } from "@medusajs/framework/utils"

export const analyticsModulePolicies = definePolicies("analytics", {
  generate_reports: "Generate analytical reports",
  export_data: "Export analytics data", 
  view_dashboards: "View analytics dashboards",
})
```

### Runtime Policy Management

Create policies dynamically through the RBAC module:

```ts title="src/admin/lib/setup-permissions.ts"
import { sdk } from "./config"

export async function createCustomPolicies() {
  // Create custom policies for your extension
  const reportPolicy = await sdk.admin.rbacPolicy.create({
    key: "custom_reports.generate",
    resource: "custom_reports",
    operation: "generate", 
    name: "Generate Custom Reports",
    description: "Allows generating custom business reports",
  })

  const exportPolicy = await sdk.admin.rbacPolicy.create({
    key: "analytics.export",
    resource: "analytics",
    operation: "export",
    name: "Export Analytics", 
    description: "Allows exporting analytics data",
  })

  return { reportPolicy, exportPolicy }
}
```

## Role Management

### Creating Roles

Define roles that group related permissions:

```ts title="src/workflows/setup-roles.ts"
import { createRoleWorkflow } from "@medusajs/medusa/core-flows"

export async function setupBusinessRoles(container) {
  // Create content editor role
  const { result: editorRole } = await createRoleWorkflow(container).run({
    input: {
      name: "Content Editor",
      description: "Can create and edit products and collections",
    },
  })

  // Add specific policies to the role
  await sdk.admin.rbacRole.addPolicies(editorRole.role.id, {
    policies: ["product:create", "product:update", "collection:*"],
  })

  // Create manager role with broader access  
  const { result: managerRole } = await createRoleWorkflow(container).run({
    input: {
      name: "Store Manager", 
      description: "Can manage products, orders, and customers",
    },
  })

  await sdk.admin.rbacRole.addPolicies(managerRole.role.id, {
    policies: [
      "product:*", 
      "order:read", 
      "order:update", 
      "customer:read",
    ],
  })
}
```

### Hierarchical Roles

Create role hierarchies with inheritance:

```ts title="src/workflows/role-hierarchy.ts"
// Create parent role
const { result: managerRole } = await createRoleWorkflow(container).run({
  input: {
    name: "Manager",
    description: "Management level access",
  },
})

// Create child role that inherits parent permissions
const { result: seniorManagerRole } = await createRoleWorkflow(container).run({
  input: {
    name: "Senior Manager",
    description: "Senior management with additional privileges",
    parent_id: managerRole.role.id,  // Inherits all manager permissions
  },
})
```

## Integration with Workflows

Check permissions within custom workflows and steps:

```ts title="src/workflows/protected-operations.ts"
import { 
  createWorkflow, 
  createStep, 
  StepResponse, 
} from "@medusajs/framework/workflows-sdk"
import { hasPermission } from "@medusajs/framework"

const checkPermissionStep = createStep(
  "check-permission",
  async ({ 
    actorId, 
    actorType, 
    resource, 
    operation, 
  }, { container }) => {
    // Check if user has permission for this operation
    const canPerform = await hasPermission({
      roles: actorId, // User ID or role IDs
      action: { resource, operation },
      container,
    })

    if (!canPerform) {
      throw new Error(
        `Insufficient permissions: ${resource}:${operation}`
      )
    }

    return new StepResponse({ authorized: true })
  }
)

export const protectedProductUpdateWorkflow = createWorkflow(
  "protected-product-update",
  (input) => {
    // Check permissions before proceeding
    checkPermissionStep({
      actorId: input.userId,
      actorType: "user",
      resource: "product", 
      operation: "update",
    })

    // Continue with protected operation...
    const updatedProduct = updateProductStep(input)

    return { product: updatedProduct }
  }
)
```

## Permission Context

Access current user permissions in your components:

```tsx title="src/admin/widgets/user-status.tsx"
import { usePermissions } from "@medusajs/dashboard"
import { Badge, Text } from "@medusajs/ui"

export default function UserStatus() {
  const { policy, isLoading } = usePermissions()

  if (isLoading) {
    return <Text>Loading permissions...</Text>
  }

  const isAdmin = policy?.permissions.includes("*:*")
  const canManageUsers = policy?.permissions.includes("user:*")

  return (
    <div className="flex gap-2 items-center">
      <Text size="small">Access Level:</Text>
      {isAdmin ? (
        <Badge color="red">Super Admin</Badge>
      ) : canManageUsers ? (
        <Badge color="blue">User Manager</Badge>
      ) : (
        <Badge color="grey">Standard User</Badge>
      )}
    </div>
  )
}
```

## Best Practices

1. **Principle of Least Privilege**: Grant only the minimum permissions needed
2. **Granular Permissions**: Use specific permissions instead of broad wildcards
3. **Consistent Naming**: Follow `resource:operation` format consistently
4. **Fallback UI**: Always provide meaningful content when permissions are missing
5. **Performance**: Permission checks are cached, so multiple calls are efficient
6. **Testing**: Test your admin extensions with different permission levels

## Complete Example

```tsx title="src/admin/widgets/advanced-product-manager.tsx"
import {
  PermissionGuard,
  RoutePermissionGuard,
  usePermissions,
} from "@medusajs/dashboard"
import {
  Button,
  Container,
  DataTable,
  Heading,
  Text,
} from "@medusajs/ui"

export default function AdvancedProductManager() {
  const { can, hasAllPermissions, policy } = usePermissions()

  // Check complex permission combinations
  const canBulkEdit = hasAllPermissions([
    "product:update", 
    "inventory:update",
  ])

  const isProductAdmin = can("product", "*")

  return (
    <RoutePermissionGuard 
      permissions={["product:read"]}
      fallback={
        <Container>
          <Text>You need product read access to use this feature</Text>
        </Container>
      }
    >
      <Container>
        <div className="flex justify-between items-center mb-4">
          <Heading>Advanced Product Management</Heading>
          
          <div className="flex gap-2">
            <PermissionGuard permissions={["product:create"]}>
              <Button variant="primary">
                Create Product
              </Button>
            </PermissionGuard>

            {canBulkEdit && (
              <Button variant="secondary">
                Bulk Edit Inventory
              </Button>
            )}

            {isProductAdmin && (
              <Button variant="danger">
                Admin Tools
              </Button>
            )}
          </div>
        </div>

        <PermissionGuard 
          permissions={["product:read"]}
          fallback={
            <Text className="text-ui-fg-muted">
              Contact your administrator for product access
            </Text>
          }
        >
          {/* Product data table with permission-based actions */}
          <DataTable>
            {/* Table implementation */}
          </DataTable>
        </PermissionGuard>

        {/* Show permission summary for debugging */}
        {process.env.NODE_ENV === "development" && (
          <div className="mt-4 p-4 bg-ui-bg-subtle rounded">
            <Text size="small" className="font-medium">
              Debug: Current Permissions
            </Text>
            <Text size="xsmall" className="text-ui-fg-muted">
              {policy?.permissions.join(", ") || "No permissions"}
            </Text>
          </div>
        )}
      </Container>
    </RoutePermissionGuard>
  )
}
```

This approach ensures your admin extensions respect user permissions and provide appropriate access control throughout your custom functionality.
