# {metadata.title}

When developing admin customizations and event subscribers, following consistent patterns and conventions ensures maintainable, error-free code. Medusa provides an ESLint plugin with rules specifically designed for admin widget, UI route, and subscriber development.

## Installation

Install the ESLint plugin in your Medusa project:

```bash npm2yarn
npm install --save-dev @medusajs/eslint-plugin
```

## Configuration

### Automatic Configuration (Recommended)

The easiest way to use the plugin is to extend the recommended configuration in your ESLint config file:

```js title="eslint.config.mjs"
import medusaPlugin from "@medusajs/eslint-plugin"

export default [
  ...medusaPlugin.configs.recommended,
  // your other ESLint configs...
]
```

### Strict Configuration

For additional rules that are more performance-intensive (including cross-file analysis), you can use the strict preset:

```js title="eslint.config.mjs"
import medusaPlugin from "@medusajs/eslint-plugin"

export default [
  ...medusaPlugin.configs.strict,
  // your other ESLint configs...
]
```

The strict configuration includes all recommended rules plus additional rules like `scheduled-job-name-unique` that ensure job names are unique across your entire project.

The recommended configuration automatically applies the appropriate rules to admin, subscriber, and scheduled job files based on their file patterns:

- Admin rules: `src/admin/**/*.{ts,tsx}` files
- Subscriber rules: `src/subscribers/**/*.{ts,js}` files
- Scheduled job rules: `src/jobs/**/*.{ts,js}` files

### Manual Configuration

For more granular control, you can configure the rules manually:

```js title="eslint.config.mjs"
import medusaPlugin from "@medusajs/eslint-plugin"

export default [
  {
    plugins: {
      "@medusajs": medusaPlugin,
    },
    files: ["src/admin/**/*.{ts,tsx}"],
    rules: {
      "@medusajs/admin-env-vars-import-meta": "warn",
      "@medusajs/admin-component-must-be-arrow-function": "error",
      "@medusajs/admin-no-medusa-utils-import": "error",
    },
  },
  {
    files: ["src/subscribers/**/*.{ts,js}"],
    rules: {
      "@medusajs/subscriber-config-export-required": "error",
      "@medusajs/subscriber-default-export-must-be-async": "error",
      "@medusajs/subscriber-default-export-required": "error",
    },
  },
  {
    files: ["src/jobs/**/*.{ts,js}"],
    rules: {
      "@medusajs/scheduled-job-config-required": "error",
      "@medusajs/scheduled-job-default-export-async": "error",
      "@medusajs/scheduled-job-default-export-required": "error",
      "@medusajs/scheduled-job-schedule-valid-cron": "error",
    },
  },
  {
    files: ["**/*.{ts,tsx,js}"],
    rules: {
      "@medusajs/import-from-framework-not-internal": "warn",
      "@medusajs/prefer-modules-enum": "warn",
      "@medusajs/use-medusa-error-not-generic-error": "warn",
      "@medusajs/no-mikroorm-direct-import": "warn",
    },
  },
  // Additional configurations for widgets and UI routes...
]
```

## Admin Development Rules

### Environment Variables

**Rule: `admin-env-vars-import-meta`**

Admin code is bundled by Vite for the browser. Use `import.meta.env` instead of `process.env` for environment variables.

```tsx
// ❌ Incorrect - process.env is undefined in the browser
const url = process.env.VITE_BACKEND_URL

// ✅ Correct - use import.meta.env
const url = import.meta.env.VITE_BACKEND_URL
```

### Framework Imports in Admin Code

**Rule: `admin-no-medusa-utils-import`**

Don't import Node-only framework modules in admin code as they break the browser bundle. These modules are designed for server-side use only.

```tsx
// ❌ Incorrect - Node-only modules break browser builds
import { MedusaError } from "@medusajs/framework/utils"
import { defineMiddlewares } from "@medusajs/framework/http"
import { createWorkflow } from "@medusajs/framework/workflows-sdk"

// ✅ Correct - Use browser-safe admin SDK
import { defineWidgetConfig } from "@medusajs/admin-sdk"

// ✅ Also correct - Types are erased at build time
import type { HttpTypes } from "@medusajs/framework/types"
```

Move server logic to workflows, API routes, or module services and call them from the admin via the JS SDK.

### Component Structure

**Rule: `admin-component-must-be-arrow-function`**

Admin widgets and UI route components must be arrow functions for consistency and hot-reloading compatibility.

```tsx
// ❌ Incorrect - function declaration
export default function MyWidget() {
  return <div>Widget content</div>
}

// ✅ Correct - arrow function
const MyWidget = () => {
  return <div>Widget content</div>
}

export default MyWidget
```

## Widget Development Rules

### Default Export

**Rule: `widget-must-have-default-export`**

Widget files must export a React component as the default export.

```tsx title="src/admin/widgets/product-widget.tsx"
// ✅ Required default export
const ProductWidget = () => {
  return <div>Widget content</div>
}

export default ProductWidget
```

### Config Export

**Rule: `widget-must-export-config`**

Widget files must export a `config` object to define widget configuration.

```tsx title="src/admin/widgets/product-widget.tsx"
import { defineWidgetConfig } from "@medusajs/admin-sdk"

const ProductWidget = () => {
  return <div>Widget content</div>
}

// ✅ Required config export
export const config = defineWidgetConfig({
  zone: "product.details.before",
})

export default ProductWidget
```

### Zone Definition

**Rule: `widget-zone-must-be-string-literal`**

Widget zones must be defined as string literals for static analysis and validation.

```tsx
// ❌ Incorrect - dynamic zone
const zoneName = "product.details.before"
export const config = defineWidgetConfig({
  zone: zoneName,
})

// ✅ Correct - string literal
export const config = defineWidgetConfig({
  zone: "product.details.before",
})
```

## UI Route Development Rules

### File Naming

**Rule: `ui-route-file-name-page-tsx`**

UI route files must be named `page.tsx` or `page.jsx` to be recognized by the admin routing system.

```
src/admin/routes/
├── brands/
│   └── page.tsx    ✅ Correct filename
├── products/
│   └── list.tsx    ❌ Incorrect - should be page.tsx
```

### Default Export

**Rule: `ui-route-must-have-default-export`**

UI route files must export a React component as the default export.

```tsx title="src/admin/routes/brands/page.tsx"
// ✅ Required default export
const BrandsPage = () => {
  return <div>Brands listing</div>
}

export default BrandsPage
```

### Route Configuration

**Rule: `ui-route-config-via-define-route-config`**

When exporting route configuration, use the `defineRouteConfig` helper for type safety.

```tsx title="src/admin/routes/brands/page.tsx"
import { defineRouteConfig } from "@medusajs/admin-sdk"

const BrandsPage = () => {
  return <div>Brands listing</div>
}

// ✅ Use defineRouteConfig helper
export const config = defineRouteConfig({
  label: "Brands",
  icon: TagSolid,
})

export default BrandsPage
```

**Rule: `no-config-on-dynamic-ui-route`**

Dynamic routes (with `[param]` syntax) should not export route configuration, as the route config only applies to static routes.

```tsx title="src/admin/routes/brands/[id]/page.tsx"
import { defineRouteConfig } from "@medusajs/admin-sdk"

const BrandDetailsPage = () => {
  return <div>Brand details</div>
}

// ❌ Config on dynamic route has no effect
export const config = defineRouteConfig({
  label: "Brand Details", // This won't be used
})

export default BrandDetailsPage
```

## Subscriber Development Rules

### Default Export

**Rule: `subscriber-default-export-required`**

Subscriber files must export a handler function as the default export.

```ts title="src/subscribers/order-placed.ts"
import type { SubscriberConfig, SubscriberArgs } from "@medusajs/framework"

// ✅ Required default export
export default async function orderPlacedHandler({
  event: { data },
  container,
}: SubscriberArgs<{ id: string }>) {
  // Handle the event...
}

export const config: SubscriberConfig = {
  event: "order.placed",
}
```

### Async Function Requirement

**Rule: `subscriber-default-export-must-be-async`**

The default-exported subscriber handler function must be async. Subscribers receive events and are always awaited by the framework.

```ts
// ❌ Incorrect - not async
export default function orderPlacedHandler() {
  // Handle the event...
}

// ✅ Correct - async function
export default async function orderPlacedHandler() {
  // Handle the event...
}
```

### Config Export

**Rule: `subscriber-config-export-required`**

Subscriber files must export a `config` object with at least an `event` property to specify which event(s) to listen for.

```ts title="src/subscribers/order-placed.ts"
export default async function orderPlacedHandler() {
  // Handle the event...
}

// ✅ Required config export
export const config: SubscriberConfig = {
  event: "order.placed", // Single event
}

// ✅ Multiple events
export const config: SubscriberConfig = {
  event: ["order.placed", "order.updated"], // Array of events
}
```

## Scheduled Job Development Rules

### Default Export

**Rule: `scheduled-job-default-export-required`**

Scheduled job files must export a handler function as the default export.

```ts title="src/jobs/hello-world.ts"
import { MedusaContainer } from "@medusajs/framework/types"

// ✅ Required default export
export default async function greetingJob(container: MedusaContainer) {
  const logger = container.resolve("logger")
  logger.info("Greeting!")
}

export const config = {
  name: "greeting-every-minute",
  schedule: "* * * * *",
}
```

### Async Function Requirement

**Rule: `scheduled-job-default-export-async`**

The default-exported scheduled job handler function must be async. Scheduled jobs are always awaited by the framework.

```ts
// ❌ Incorrect - not async
export default function greetingJob() {
  // Handle the job...
}

// ✅ Correct - async function
export default async function greetingJob() {
  // Handle the job...
}
```

### Config Export

**Rule: `scheduled-job-config-required`**

Scheduled job files must export a `config` object with `name` and `schedule` properties.

```ts title="src/jobs/hello-world.ts"
export default async function greetingJob() {
  // Handle the job...
}

// ✅ Required config export
export const config = {
  name: "greeting-every-minute",    // Unique job name
  schedule: "* * * * *",           // Cron expression or interval object
}
```

### Valid Cron Expression

**Rule: `scheduled-job-schedule-valid-cron`**

When using cron-based scheduling, the `config.schedule` value must be a valid cron expression.

```ts
// ❌ Incorrect - invalid cron expression
export const config = {
  name: "my-job",
  schedule: "* * * *", // Missing required field
}

// ✅ Correct - valid cron expression
export const config = {
  name: "my-job",
  schedule: "0 0 * * *", // Daily at midnight
}

// ✅ Also correct - interval-based scheduling
export const config = {
  name: "my-job",
  schedule: { interval: 60000 }, // Every minute
}
```

### Unique Job Names

**Rule: `scheduled-job-name-unique`** (strict preset only)

Each scheduled job must have a unique `name` across all job files in the project.

```ts title="src/jobs/sync-products.ts"
export const config = {
  name: "sync-products", // ❌ If another job already uses this name
  schedule: "0 0 * * *",
}
```

```ts title="src/jobs/daily-cleanup.ts"
export const config = {
  name: "sync-products", // ❌ Duplicate name - will cause conflict
  schedule: "0 1 * * *",
}
```

**Note:** This rule is only enabled in the `strict` preset as it requires cross-file analysis and can be slower on large projects.

## General Development Rules

### Framework Imports

**Rule: `import-from-framework-not-internal`**

Use the public `@medusajs/framework/*` entry points instead of deprecated standalone packages or internal build output.

```ts
// ❌ Incorrect - deprecated standalone package
import { MedusaError } from "@medusajs/utils"

// ✅ Correct - use framework entry point (autofix available)
import { MedusaError } from "@medusajs/framework/utils"

// ❌ Incorrect - internal dist import
import { foo } from "@medusajs/medusa/dist/utils/foo"

// ✅ Correct - use public API
import { foo } from "@medusajs/framework/utils"
```

**Rule: `no-mikroorm-direct-import`**

Don't import MikroORM or awilix directly. As of Medusa v2.11, they're bundled into `@medusajs/framework`.

```ts
// ❌ Incorrect - direct MikroORM import
import { EntityManager } from "@mikro-orm/core"
import { Container } from "awilix"

// ✅ Correct - use framework re-exports (autofix available)
import { EntityManager } from "@medusajs/framework/mikro-orm/core"
import { Container } from "@medusajs/framework/awilix"
```

### Module Resolution

**Rule: `prefer-modules-enum`**

Use the `Modules` enum instead of magic strings when resolving modules from the container.

```ts
// ❌ Incorrect - magic string
const productService = container.resolve("product")

// ✅ Correct - use Modules enum (autofix available)
import { Modules } from "@medusajs/framework/utils"
const productService = container.resolve(Modules.PRODUCT)
```

### Error Handling

**Rule: `use-medusa-error-not-generic-error`**

Throw `MedusaError` instead of generic JavaScript errors. `MedusaError` carries a `type` that Medusa maps to the correct HTTP status and consistent client response.

```ts
// ❌ Incorrect - generic Error
throw new Error("Something went wrong")

// ✅ Correct - MedusaError with appropriate type
import { MedusaError } from "@medusajs/framework/utils"
throw new MedusaError(MedusaError.Types.NOT_FOUND, "Order not found")
```

## Benefits

Using the ESLint plugin provides several advantages:

1. **Consistency**: Enforces consistent patterns across your admin customizations, subscribers, and scheduled jobs
2. **Early Error Detection**: Catches common mistakes before runtime, including invalid cron expressions and configuration errors
3. **Better Developer Experience**: Provides immediate feedback with auto-fixing capabilities
4. **Framework Compatibility**: Ensures your code works correctly with Medusa's admin, event, and job scheduling frameworks
5. **Maintainability**: Makes your codebase easier to maintain and debug

## IDE Integration

Most modern code editors automatically pick up ESLint configuration. For the best development experience:

1. **VS Code**: Install the ESLint extension
2. **Enable auto-fix on save** in your editor settings
3. **Configure your editor** to show ESLint warnings and errors inline

This provides real-time feedback while developing admin customizations, subscribers, and scheduled jobs.
