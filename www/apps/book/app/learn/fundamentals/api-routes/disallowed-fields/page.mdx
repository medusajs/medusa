# {metadata.title}

In this chapter, you'll learn about disallowed fields in API routes, how to apply them to custom API routes, and how to override them for Medusa's API routes.

<Note>

The `disallowed` query configuration is available since Medusa [v2.18.0](https://github.com/medusajs/medusa/releases/tag/v2.18.0).

</Note>

## What are Disallowed Fields?

Some of Medusa's API routes block specific field path segments as a hard security boundary. Medusa removes these fields from the query before it executes, regardless of what the client requests.

Disallowed fields guard sensitive relations, such as orders, customers, and payment data, on unauthenticated Store API routes. This prevents a client from pivoting from a public resource into private data.

For example, a Store API route for products blocks the `orders` segment. So, a request to `GET /store/products?fields=orders.customer.email` returns products without the `orders` relation, even if the client explicitly requests it.

Disallowed fields are different than [allowed fields](../retrieve-custom-links/page.mdx#api-routes-that-restrict-retrievable-fields):

- Allowed fields are an opt-in list of the fields a route can retrieve. Medusa applies them to keep API routes performant and secure.
- Disallowed fields are a deny list that Medusa always enforces, even if the field is in the allowed list, and even if the client requests it explicitly.

---

## How to Disallow Fields in Custom API Routes?

If you create a custom Store API route and want to apply the same protection, pass a `disallowed` array to the `validateAndTransformQuery` configuration:

export const disallowHighlights = [
  ["18", "disallowed", "The field path segments to always strip from the query."],
]

```ts title="src/api/middlewares.ts" highlights={disallowHighlights}
import {
  validateAndTransformQuery,
  defineMiddlewares,
} from "@medusajs/framework/http"
import { createFindParams } from "@medusajs/medusa/api/utils/validators"

export default defineMiddlewares({
  routes: [
    {
      matcher: "/store/custom",
      method: "GET",
      middlewares: [
        validateAndTransformQuery(
          createFindParams(),
          {
            defaults: ["id", "title"],
            isList: true,
            disallowed: ["orders", "customer"],
          }
        ),
      ],
    },
  ],
})
```

Medusa strips any field path that contains `orders` or `customer` as a segment from the query before it executes.

Each entry of the `disallowed` array is either:

- A string, which Medusa matches against a whole field path segment. So, `orders` also blocks `orders.customer.email`.
- A regular expression, which Medusa tests against each segment, such as `/_link$/`, and against the full dotted path. This allows you to block a relation at a specific position. For example, `/\.orders(?:\.|$)/` blocks `orders` everywhere but at the root.

## How to Override Disallowed Fields of Medusa's API Routes?

<Note>

Overriding disallowed fields is available since Medusa [v2.20.2](https://github.com/medusajs/medusa/releases/tag/v2.20.2).

</Note>

Medusa's Store API routes disallow the field path segments of sensitive relations, including custom links whose name ends with `_link`. If your use case requires retrieving one of these segments, you can override the disallowed fields of an API route.

<Note title="Warning" type="warning">

Disallowed fields protect sensitive data from clients that only have a publishable API key. Setting the `disallowed` property to an empty array removes that protection from the route.

</Note>

To do that, apply a [global middleware](../middlewares/page.mdx) that sets the `disallowed` property of the request object. Medusa then enforces the fields you set instead of the ones configured by the route, similar to [overriding allowed fields](../retrieve-custom-links/page.mdx#how-to-override-allowed-fields-and-relations).

Since the property replaces the route's disallowed fields, set it to the fields that Medusa disallows minus the ones you need, rather than to a short list of your own. Medusa exports the lists that its Store API routes use, so you can filter one of them:

- `disallowedStoreFields`: used by public routes, such as the product and region routes.
- `disallowedStorePivotFields`: used by routes that expose the requesting caller's own cart, order, or customer data, such as the cart and order routes.
- `disallowedStoreCustomerFields`: used by the customer routes.

For example, to retrieve the campaign applied to a cart's promotions on the [Get Cart Store API Route](!api!/store/carts/get-a-cart), create the file `src/api/middlewares.ts` with the following content:

export const highlights = [
  ["10", "disallowed", "Enforce these fields instead of the route's fields."],
  ["10", "filter", "Remove the segment that blocks the campaign relation."],
]

```ts title="src/api/middlewares.ts" highlights={highlights}
import { defineMiddlewares } from "@medusajs/medusa"
import { disallowedStorePivotFields } from "@medusajs/medusa/utils"

export default defineMiddlewares({
  routes: [
    {
      matcher: "/store/carts/:id",
      middlewares: [
        (req, res, next) => {
          req.disallowed = disallowedStorePivotFields.filter(
            (field) => field !== "campaign"
          )
          next()
        },
      ],
    },
  ],
})
```

In this example, you apply a middleware to the [Get Cart Store API Route](!api!/store/carts/get-a-cart). The middleware sets the `disallowed` property of the request object to the fields that Medusa disallows on routes exposing the caller's own cart data, except for the `campaign` segment.

You can now retrieve the campaign of a cart's promotions using the `fields` query parameter:

```bash
curl 'http://localhost:9000/store/carts/{id}?fields=*promotions.campaign' \
-H 'x-publishable-api-key: {your_publishable_api_key}'
```

Medusa still strips the other disallowed segments, such as `orders` and `customers`, from the query.

You can also use the `disallowed` property to block more segments on an existing API route:

```ts title="src/api/middlewares.ts"
req.disallowed = [...disallowedStorePivotFields, "payment_collection"]
```

<Note title="Important">

This approach only works using a global middleware, since Medusa applies the disallowed fields in a route middleware. It also only applies to the request that the middleware handles, so it never leaks into other requests.

</Note>
