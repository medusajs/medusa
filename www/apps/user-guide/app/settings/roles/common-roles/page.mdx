# {metadata.title}

<EnterpriseNotice />

This guide suggests common roles you can create in the Medusa Admin and the policies each one typically needs. Use it as a starting point, then adjust the policies to match how your team works.

<Note title="Enterprise feature">

Roles and policies are part of the role-based access control (RBAC) feature, which is an enterprise feature. A developer must enable it in your Medusa configuration before the **Roles** and **Policies** settings appear.

</Note>

## How to Read This Guide

Each policy is written as `resource:operation`, where the operation is one of `read`, `create`, `update`, or `delete`. For example:

- `product:read` allows viewing products.
- `product:create` allows creating products.

In the Medusa Admin, you select each policy individually. Operations are independent: granting `product:update` doesn't also grant `product:read`. So, to give a role full access to a resource, select all four of its operations.

Roles also often need `read` access to related resources to use a page without errors. For example, a product manager needs `sales_channel:read` to assign products to sales channels. These related policies are listed for each role below.

To find the exact policy keys available in your store, browse the [Policies](../../policies/page.mdx) list in the dashboard.

To create any of these roles, follow the steps in the [Manage Roles](../page.mdx#create-a-role) guide and select the listed policies.

---

## Super Admin

A super admin has full access to the store, including managing roles and policies.

To create this role, select all available policies so the role can perform every operation on every resource.

<Note title="Tip">

Medusa already provides a built-in Super Admin role with full access. You only need to create a custom role like this if you want to manage it yourself.

</Note>

## Read-Only Analyst

A read-only analyst views data across the store without making changes.

To create this role, select the `read` operation for every resource, such as `product:read`, `order:read`, and `customer:read`. Don't select any `create`, `update`, or `delete` operations.
